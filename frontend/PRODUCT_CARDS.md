# 聊天商品卡片

依据 [商品卡片接口说明](../docs/商品卡片接口说明.md) 与 [账号与历史接口说明](../docs/账号与历史接口说明.md)。仅展示 JSON 响应或 SSE `done` 中的可选 `products`，沿用接口顺序。后端默认最多六张，`PRODUCT_CARDS_MAX` 可配置为 1–12，组件跟随后端实际返回数量，另有共用解析器的 12 张及体积保护。名称、品类及一至两条 `highlights` 按纯文本展示，无价格、库存或商品链接。「资料关联商品」包括引用资料关联及回答中全称或“系列+型号”别名命中的商品，不表示逐项推荐。别名从商品表 `series` 与名称中紧跟系列的字母数字型号推导，例如 `栖光 L3`；只写 `L3` 不匹配，同型号靠系列名区分，全称优先、引用 SKU 优先去重，详情见接口说明。前端不自行推导或补造商品。

## 图片部署

- 完整 HTTP(S) `image_url` 直接使用。
- 相对路径 `<sku>/main.webp`（及接口允许的 PNG/JPG/JPEG/SVG）使用图片根地址拼接：**未设置 `VITE_PRODUCT_IMAGE_BASE_URL` 时默认同源 `/images`**（由 `deploy/Caddyfile` 的 `handle_path /images/*` 托管 `data/images`，需设置环境变量 `ECOMRAG_IMAGES_DIR` 为该目录的绝对路径）；也可构建时显式设置，例如 `https://images.example.com/products` 或同源 `/products`。图片根地址与 `VITE_API_BASE` 独立，配置路径前缀会被保留。
- 图片为空、URL 无效或加载失败，统一显示组件内 SVG/文字占位，无额外占位文件请求。图片与占位使用同一 `product-card-image aspect-square` 正方形容器（1:1），图片以 `object-cover` 铺满，使用商品名 alt 与懒加载。非方图会按容器裁切，源图片内部自带的留白不会被移除。
- 前端不提供静态图片服务或改动代理。部署方需确定公开图片根地址，并托管后端 `data/images/`；若后端 `IMAGE_BASE_URL` 已生成完整地址，无须额外前端配置。

## 显示与历史

聊天页右下角的「店铺商品」悬浮入口用于浏览商品品类，独立于回答下方的商品卡片。入口最终采用方案 D：白底、1.5px 黑色边框、胶囊圆角，与店名一致的黑色衬线字体、17px 字号、3px 字距及文字后方的 7px 橙点。橙点复用 `spark`（仓库 logo 实际色值 `#E07A3F`）；悬停黑底白字、上浮 2px，橙点保持。所有屏幕宽度下均可操作，推荐问题展开时也保留。输入区底部为其预留 2.75rem 高度、1rem 间距及安全区（默认字号下为 44px/16px），右侧至少留 24px，避免与输入、发送、问题胶囊及滚动条重叠。弹窗顶部为顶栏同款 logo、店名与介绍，后面直接接商品品类，右上角保留关闭；省去可见的通用标题、模拟店铺提示、客服和承诺小节。品类选择只填入草稿，不自动发送或补造商品卡片，沿用现有静态店铺数据及接口契约。详见 [前端说明](README.md)。

手机单列，≥640px 的平板/窄桌面两列，≥1024px 的宽桌面三列。网格使用 `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 items-stretch`；通过与 CSS 断点一致的 `matchMedia` 查询按当前 1/2/3 列分组，监听窗口变化并在卸载时移除监听。每行共享展开状态，点击同行任意名称按钮会同步展开或收起整行，其他行和其他回答的网格互不影响；单列时只切换当前卡片。末行不足列数时只切换该行实际存在的商品。同行卡片由网格拉齐高度，保留正方形图片；不同内容长度不会造成卡片外侧的大块空白。跨断点改变列数时重新分组并收缩全部详情；在同一列数内调整宽度保留展开状态。多行在聊天正文内自然增高，`min-w-0 max-w-full` 与详情换行限制横向溢出，沿用聊天区滚动。

信息区默认全部收缩，只显示一行完整 SKU 名称的文本（过长时省略号，按钮可访问名称仍保留全称）与左侧三角指示（收起朝右、展开朝下）。点击名称按钮展开同行商品各自的品类和 1–2 条要点，再点收起；行标识由实际成员 SKU 组成，商品列表变化后不将展开状态套到不同成员的新行。每张卡的原生 `<button type="button">` 支持 Tab 聚焦及 Enter/Space 激活，通过 `aria-expanded` 与唯一 `aria-controls` 关联自身详情；同行按钮的 `aria-expanded` 同步更新，收起内容使用 `hidden`。商品卡片、引用来源与链路统一使用 `index.css` 的 `disclosure-panel/trigger/marker`：`card` 白底、`ink` 文字、`line` 细边框、12px 圆角，标题 13px/中等字重、水平内边距 16px、垂直 12px、至少 44px 高。品类和规格使用 `muted/body-muted`，焦点描边放在按钮内避免被卡片裁切；图片占位仍沿用深色媒体查询。

流式仅显示增量文字，最终事件后挂载卡片。重试/重新生成沿用替换整条助手消息的行为，开始时移除旧卡片，并从请求上下文排除被替换的回答。

服务器历史契约仅保存正文、route、sources，不保存 `products`。当前页面刚生成的回答可展示卡片，重新打开服务器历史后不展示，不从型号、正文或引用伪造，也不额外查询商品。

访客本地历史沿用现有消息结构保留卡片：只保留 `sku/name/category/highlights/image_url`，共用解析最多十二张和两条规格，限制字段长度，全部卡片紧凑 JSON（含转义）的 UTF-8 总计不超过 16 KiB。本地保存时也参考 32 KiB 单消息预算逐张移除超出预算的卡片；若原消息正文、来源等已超过预算，则仅省略卡片，保留原有历史行为。已有本地历史总量 2 MiB 字符上限和配额失败内存回退仍生效；没有卡片的旧消息兼容。服务端规定的单条消息 32 KiB 上限仍由后端执行，前端不会将卡片上传到历史接口或模型上下文，请求 `history` 始终仅含既有的 `{role, content}`。展开状态不持久化，重新挂载后默认收缩。

## 验证

组件测试覆盖一/二/三/六/十二张顺序渲染、默认收缩、1/2/3 列同行同步展开/收起、行间和网格间独立、末行不足列数、639/640/641 与 1023/1024px 边界、连续缩放重分组及同列数内状态保留、成员变化、监听清理、唯一 ARIA 关联、Tab 与 Enter/Space 同行操作、单行名称、方形图片和失败占位、`object-cover`、共用折叠样式与左侧三角以及同行等高；`Trace.test.tsx` 从真实 Tailwind 配置编译样式，校验白底、细边框、圆角、字号、内边距和三角旋转规则。保留纯文本规格及旧回答兼容测试。API、完整聊天与历史原有测试继续覆盖 JSON/SSE 最终事件、重试/重新生成清除、本地恢复和服务器历史不补造卡片。布局和颜色仍需浏览器验证，DOM/CSS 测试不能替代视觉检查。

本次沙箱中已尝试 `VITE_SKIP_ENV_FILES=1 npm test` 与 `VITE_SKIP_ENV_FILES=1 npm run build`，两者均在启动前被拒绝，输出 `zsh:1: operation not permitted: npm`（退出码 127）。因此测试及构建尚未经运行验证，布局也未在浏览器实测；需在允许 Node/npm 的环境执行上述命令。`VITE_SKIP_ENV_FILES=1` 使用项目已有配置关闭本地环境文件加载。未安装依赖、读取 `.env*`、连接外部服务或提交。

本次功能无新增待定项。原有部署方需确定的公开图片根地址及托管方式不变。
