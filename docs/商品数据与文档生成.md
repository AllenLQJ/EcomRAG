# 商品数据与文档生成

商品事实的唯一维护入口是 `data/products/products.csv`，UTF-8 编码。全部商品为灵码模拟店铺设定，`source` 固定为 `simulated`，不代表真实品牌或实物认证。现有四款的参数、测试条件及否定说明来自 `data/docs`，新增四十六款用于离线知识数据准备。

共 50 款：听岚无线耳机 8 款、栖光桌面台灯 6 款、木澈保温杯 6 款、鸣澜蓝牙音箱 6 款、衡电充电设备 6 款、联枢数据线与配件 5 款、键行键盘鼠标 6 款、纳境收纳包 4 款、沐息香薰加湿 3 款。听岚只保留原有 S1、S2，不新增 S 系列编号。

生成物放在 `data/docs_generated/`，与原有 19 篇 `data/docs/*.md` 分开，不改变 FAQ、检索、评测、前端、线上接口或现有 ingest pipeline。原目录中的四款总览继续供现有流程使用；本任务产出的五十款总览仅作为待接入资料。工具会拒绝将文档输出到 `data/docs` 及其子目录。

## CSV 字段

固定表头与顺序如下，不增加商业字段。本店口径：价格以商品页为准；数据表不存价格、库存或促销信息。

| 字段 | 规则与用途 |
| --- | --- |
| sku_id | 主键；小写英文字母、数字及段间连字符，最长 64 字符，例如 `tinglan-s1`；全表唯一 |
| name | 完整商品名，最长 160 字符，全表唯一；不加“灵码”前缀，文档标题由工具添加 |
| series | 听岚、栖光、木澈、鸣澜、衡电、联枢、键行、纳境、沐息，与品类对应 |
| category | 下表列出的九个中文品类之一 |
| tagline | 一句卖点，不超过 30 字符 |
| positioning | 定位一句话，写清适用场景与取舍 |
| specs | JSON 对象字符串，键为中文参数名，值为非空字符串；数值附单位，非数值规格如“不防水”“无电池”直接写明 |
| package_contents | 包装中实际包含的物品，不从图片反推赠品 |
| not_included | 明确不含物品；可为空，不以空值推断赠品 |
| usage_notes | 使用步骤、场景及维护注意事项；原四款保留原文中的使用事实和比较说明 |
| caveats | 测试条件、参数口径及限制，保留“不承诺…”等谨慎表述 |
| related_skus | 分号连接其他已存在的 sku_id；可为空，不引用自身；比较段从被引用行读取定位和参数 |
| image_main | 相对 `data/images/` 的路径，限定 `<sku_id>/main.webp`、`.png`、`.jpg`、`.jpeg` 或 `.svg`；当前均为最终目标 `main.webp` |
| image_alt | 可见外观的替代文字，同时用于图片提示与 SVG 无障碍描述 |
| source | 固定 `simulated` |

推荐用支持 CSV 引号转义的表格工具或 Python `csv` 编辑。`specs` 在单元格中是 JSON，CSV 会将内部双引号再转义，例如逻辑值 `{"容量":"450 毫升"}`。字段内容不允许换行，表格中的竖线由生成器转义。

校验器检查表头和列数、必填值、主键和名称唯一性、品类与系列、JSON 对象及重复键、中文参数名、必填参数、关联引用、图片路径与来源。纯数字字符串会被拒绝；多值参数应写全单位与测试条件。任何普通字段或参数键值出现 `元`、`¥`、`￥`、`价格`、`售价`、`促销`、`库存`、`现货` 或 `现货数量` 均报错，包括“单元”等含有“元”的词。唯一例外为 `specs` 中准确名为“运费门槛”的键值；它不是新增表头，也不能用于其他商业信息。

## 跨字段一致性与文案差异校验

`validate` 在基本字段校验后执行以下离线检查；导入与生成命令共用同一入口，校验失败不产生输出或数据库写入。

- 在“电池…”或“供电方式”等能力参数中识别“无电池”“不含电池”“无内置电池”“没有内置电池”。“65 克（不含电池）”属于重量口径，不会把使用可更换 AA 电池的 M1 误判为无需电池。
- 对无电池款的 `usage_notes`、`caveats`、`package_contents` 禁止肯定的“电池、电芯、续航、满电、充电宝、充满”表述。台灯、键鼠和加湿设备另禁止自身“充电、补电、充足电”的话术；充电器允许描述给外设充电，但不能谈自身电芯、容量或续航，也不能混用充电宝描述。
- 对仅有线连接的键鼠，禁止上述三个字段肯定描述蓝牙、配对、接收器、无线、电池或充电。明确不支持充电的无线鼠标不得包含 C 型线或充电线，也不得描述自身可充电。M1 保持 AA 电池规格，已去掉包装中的 C 型线；M2 的线材仅用于其已声明的充电功能，不擅自增加有线数据模式。
- 仅豁免紧邻关键词的明确否定，如“无电池”“不含充电电池”“不支持充电”；原 L1 的“不能把供电线理解为充满一次就能脱线使用”也保留。一个句子中出现“不”不会使后面另一分句的肯定能力自动豁免，“不承诺”也不能掩盖不具备的电池规格。
- 防护检查覆盖使用、限制、包装、卖点、定位和替代文字。未标注等级或不防水的商品不能宣称防水、防泼溅或 IPX 等级；已标注的 IPX 数字必须匹配。耳机与充电盒分别核对，耳机的 IPX5 不会赋予不防水充电盒同样能力。明确否定的“不防水”“不承诺防水”可以保留。
- 每个品类任意两款的 `usage_notes + caveats` 去掉标点和空白、英文转小写，取连续 3 字符 n-gram 集合，计算 Jaccard（交集/并集）；严格超过 0.85 报错，列出两个 SKU 与分数。共享保修模板不参与比较；每款至少以两句独有的规格说明表达选择差异，不能只换型号名绕过检查。

本次通读全表后重写了除原四款外的全部 46 款使用与限制说明：耳机 6 款、台灯 5 款、保温杯 5 款、音箱 6 款、充电设备 6 款、数据线与配件 5 款、键鼠 6 款、收纳包 4 款、香薰加湿 3 款。具体 sku_id 与完整名称见文末清单，排除开头的 tinglan-s1、tinglan-s2、qiguang-l1、muche-c1。

## 命令流程

以下命令在仓库根目录执行。也可先进入 `backend` 再执行 `python -m ingest...`，省略 `PYTHONPATH=backend`；`data/...` 路径始终以仓库根目录解释，其他相对路径以当前工作目录解释。使用项目的 Python 3.11 环境。

```sh
PYTHONPATH=backend python -m ingest.products validate
PYTHONPATH=backend python -m ingest.products generate --out data/docs_generated
PYTHONPATH=backend python -m ingest.products image-prompts
PYTHONPATH=backend python -m ingest.products placeholders
```

校验其他 CSV 时，将全局参数放在子命令前，例如 `python -m ingest.products --csv /path/to/products.csv validate`。校验不要求永远恰好五十行，便于后续维护；当前提交的数据与测试固定检查五十款及指定品类数量。文档生成要求保留原四款，先完成全部事实回归再写文件。

每个 SKU 输出 `data/docs_generated/product_<sku_id>.md`，包含标题、参数表、参数口径与限制、使用与口径、与相关款比较、保养与售后。总览 `product_catalog.md` 按品类列出 SKU、定位、参数与选购方向，保留“你这里有什么商品？你们卖什么？”标题，结尾数量从 CSV 行数生成。另输出同步后的 `after_sales_warranty.md`，目前共 52 份文档。总览覆盖九类且无“4 款”残留，原 `data/docs` 中的总览与政策保持原状。

在 `data/products/image_prompts.md` 查看统一风格及每款描述。用户自行生成真实图片并放入 `data/images_src/<sku_id>/`，然后执行：

```sh
PYTHONPATH=backend python -m ingest.products images-build
PYTHONPATH=backend python -m ingest.load_products data/products/products.csv --dry-run
PYTHONPATH=backend python -m ingest.load_products data/products/products.csv
```

`images-build` 的 Pillow 是可选依赖，仅执行此命令时延迟导入；未安装会提示 `python -m pip install Pillow` 并以非零状态退出。其余数据、提示词及 SVG 命令仅依赖标准库。此任务不安装依赖、不调用图片模型、不联网，不自动启动或连接服务；上述非 dry-run 数据库命令由使用者在准备好环境后执行。

## 占位图与真图替换

- `placeholders` 生成 `data/images/<sku_id>/main.svg` 与同名标记 `main.placeholder`。SVG 使用品类低饱和底色、几何图形、商品名称与“占位图”，可直接提交。几何图形只是品类示意，不表示实物外形。
- CSV 的 `image_main` 是最终真图目标路径，缺少真图时可通过 `main.placeholder` 识别并使用同目录的 `main.svg`；本任务不修改前端来接入此规则。
- 原图支持 `.png`、`.jpg`、`.jpeg`、`.webp`，扩展名大小写均可。每款优先选文件主名为 `main` 的原图，否则按文件名排序取第一张；建议每款只放一张确认好的原图。可用 `images-build --src /path/to/images_src` 指定其他来源目录。
- 构建时校正 EXIF 方向，将透明区域合成到浅灰底上，按比例缩小为 `main.webp`（最大约 800px 宽）和 `thumb.webp`（最大约 320px 宽），不放大小图、不裁切，建议原图至少 1024 × 1024。编码质量为 85。
- 真图构建成功后删除该款 `main.placeholder`，保留原 SVG 作为后备。再次运行 `placeholders` 会跳过已有 `main.webp/png/jpg/jpeg` 的 SKU，不覆盖真图、不重新加标记。缺少原图的 SKU 会逐一报告；已有真图保持原状，其余补齐或保留占位图。原图损坏时报告 SKU 并退出，不移除占位标记。
- SVG、WebP、PNG、JPG 真图均可提交；`.gitignore` 仅新增 `data/images/**/*.tmp`，构建成功或失败后清理临时文件。没有添加忽略整个图片目录的规则，也不自动删除用户原图。

## 事实一致性与售后模板

语料提升后，四份下划线旧文件已删除，回归基准改为线上连字符版本。每次 `generate` 都读取仓库内真实的 `product_tinglan-s1.md`、`product_tinglan-s2.md`、`product_qiguang-l1.md`、`product_muche-c1.md`。按原参数项逐项比较生成文档自身的参数表，忽略空白，要求原数值、单位、测试条件及非数字规格文字一致；比较段中出现其他款的数字不会被误当作本款参数。失败时列出 SKU、参数项、原值与生成值，不输出部分文档。原文中含“不”“无”“不能”“没有”的完整限制句也须保留。原文件只作为回归基准，生成器不从中补写 CSV 缺失事实。WAR-02 模板升级仅允许精确的旧杯体保修固定句映射到新固定句；新句缺失或其他否定限制丢失仍报错。

原四款的使用说明、测试条件和比较事实保存在 CSV 中，原售后固定句由品类模板生成，避免逐款改写。每款模板统一包含：

> 签收之日起 7 天内商品存在质量问题可申请退货，运费由店铺承担。外观类问题需提供开箱照片或视频，客服 1–2 个工作日内审核。

售后规则唯一来源为 `data/policy/policy_facts.csv` 的 WAR-01/WAR-02。电子品类统一使用“自签收起 12 个月有限保修，针对正常使用下确认的非人为功能故障。”保温杯使用“杯体制造缺陷保障期为 6 个月，密封圈等正常磨损部件不作永久更换承诺。”收纳包使用“收纳包制造缺陷保障期为 6 个月，拉链、五金等正常磨损部件不作永久更换承诺。”当前香薰加湿三款全部为外接电源电子产品，均使用电子类模板。未来若新增非电扩香用品，应先明确独立分类与模板，不套用当前规则。

同步政策以 CSV 中实际存在的品类生成适用范围：电子类自签收起 12 个月有限保修，保温杯、收纳包按 6 个月制造缺陷保障，密封圈/拉链/五金等正常磨损部件不作永久更换承诺。生成器只替换原 `after_sales_warranty.md` 第一段范围文字，原标题、全部章节、保修与退货区别、不适用情形、维护建议及其正文保持逐字一致；更新版本只写入 `data/docs_generated/`，不维护一份手写的九品类政策文本。

## MySQL 建表与导入

独立 DDL 为 `backend/ingest/products_schema.sql`，列与 CSV 一一对应，`sku_id` 为大小写敏感主键，`specs` 使用 MySQL JSON 列，不增加商业字段。`load_products` 先幂等建表再开始导入；也可单独运行 `PYTHONPATH=backend python -m ingest.migrate_products` 建表。不会修改现有 `migrate_db.py`、FAQ 仓库或线上接口。

连接沿用现有 PyMySQL 的 `utf8mb4`、超时、关闭连接与事务处理风格，数据库驱动延迟导入。配置仅从已注入配置或进程环境 `MYSQL_HOST/PORT/USER/PASSWORD/DATABASE` 获取，不读取任何 `.env*`。默认连接地址为 `127.0.0.1:3306`，默认数据库与用户为 `ecomrag`，默认密码为空。凭据不写入资料或异常输出。`--dry-run` 只校验与打印计划，不导入驱动、不加载应用配置、不建表、不连接数据库。

导入按 `sku_id` 执行参数化 `INSERT ... ON DUPLICATE KEY UPDATE`，重复导入更新原行，默认保留数据库中的其他 SKU。命名锁使商品导入串行执行；本批 upsert 和可选删除共用一个 DML 事务，失败回滚并释放锁。MySQL DDL 自带隐式提交，因此建表与后续数据回滚分开处理。若需删除 CSV 中不存在的数据库行，必须显式同时指定两个参数：

```sh
PYTHONPATH=backend python -m ingest.load_products data/products/products.csv --dry-run --prune --yes
PYTHONPATH=backend python -m ingest.load_products data/products/products.csv --prune --yes
```
