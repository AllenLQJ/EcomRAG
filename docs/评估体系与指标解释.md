# 离线 RAGAS 质量评估

评估分为 `collect`（采集）和 `score`（打分）两阶段，独立于 HTTP 服务生命周期。
`/api/v1/chat` 与 `/api/v1/chat/stream` 不启动评估，也不增加响应字段。
本功能复用 `eval/run_eval.py` 的 Settings 白名单、commit、数据 SHA256 前 12 位和 prompt 指纹；
原有路由、来源命中率、拒答与耗时报告继续由 `run_eval` 提供，RAGAS 补充生成质量视角。

## 采集与样本格式

`collect` 直接经 Services 调用 Pipeline，不走 HTTP。仅此调用显式传入 `collector` 回调；
默认 `None` 时不构造上下文副本、不导入评估模块、不增加模型调用。
记录最终 answer、实际 route、归一化后的 history、sources，以及送给 Generator 的全部上下文。
采集记录另有 `intent`（general/knowledge/sensitive/faq/cache）与 `refuse_reason`
（sensitive/no_docs/low_score/no_answer；未拒答为 null），这两个字段不进入 HTTP ChatResponse。
`contexts` 按筛选后的生成顺序编号，保留 `index/doc_id/title/score/text`；
`text` 是 `[编号] 标题\n完整正文`，对应 Generator 在 XML 转义前的单条资料文本。
它包含未被答案引用的资料；响应 sources 仍只保留引用项，编号与 contexts 一致，可能不连续。
Generator 已调用但最终拒答的 fallback 仍可在采集文件中保留上下文，打分时列为不适用。

适配器将 question/answer/contexts/reference 映射为 RAGAS 的
`user_input/response/retrieved_contexts/reference`。黄金集的 `scenario/risk/answerable/reviewed/source_version`
保留用于分组和复核；`answerable=false` 不会被自动剔除，是否适用由实际路由决定。
历史保存在采集文件中；当前四个指标按单轮问题评分，不会把 history 拼入问题或当成事实资料。

`data/eval_ragas_gold.jsonl` 是草稿，`reviewed=false` 表示参考答案尚待人工确认。
运行前应明确数据版本；评分无法修复错误的 reference。

## 四个指标

| 指标（CLI 名） | 衡量内容 | 必需输入 | 解释 |
| --- | --- | --- | --- |
| Faithfulness（`faithfulness`） | 答案中的可核验陈述是否得到本次检索上下文支持 | question、answer、retrieved_contexts | 通常是有证据支持的陈述占比；高分不代表资料本身真实或完整 |
| Response Relevancy（`response_relevancy`） | 回答是否切合用户问题 | question、answer、Judge、embedding | 利用答案反向生成问题并比较语义相关性；不能单独衡量事实正确性 |
| Context Precision（`context_precision`） | 相关资料是否排在检索结果前列 | question、retrieved_contexts、reference | 使用带参考答案的 LLMContextPrecisionWithReference；考察按顺序的检索精度，不等同于向量/重排 score |
| Context Recall（`context_recall`） | 参考答案的事实是否被检索上下文覆盖 | reference、retrieved_contexts | 使用 LLMContextRecall；遗漏证据会降低分数，reference 不完整会影响解释 |

各指标通常在 `[0,1]` 范围内。缺失输入、非数值、越界、NaN、Infinity 均为 `invalid`。
Judge 超时、解析失败或其他异常为 `error`；真实合法的 `0` 才是零分。
不把这些指标简单平均成一个综合分，以免掩盖检索与生成的不同问题。

## 分母与异常口径

- 报告保留所有采集行。FAQ/cache/general/sensitive/fallback 单列 `not_applicable` 及路由数量，不强算 Faithfulness=0。
  对外敏感拒答仍是 route=fallback；`not_applicable_by_route` 保留该真实路由统计，
  `not_applicable_by_category` 根据 intent/refuse_reason 将 sensitive 与普通 fallback 分别计数。
  旧采集文件缺这两个字段时记为 unknown；无法区分敏感/普通拒答的旧 fallback 单列 unknown，不反推其意图。
- 仅实际 rag 且存在上下文的前 `--max-samples` 行进入预算，默认 50；按采集顺序确定，不随机抽样。
  其余 RAG 行为 `skipped_limit`。非 RAG 不占预算；预算内缺输入的 RAG 行仍占该行名额。
- 缺少 reference 只使 context_precision/context_recall 为 `invalid`，其余指标仍可评分。
  rag 缺上下文为 `invalid`，采集失败为 `error`，都保留在逐行记录、失败列表及统计中。
- 逐指标 `scorable` 表示输入满足要求的行（含预算外 RAG 行），`attempted` 为实际调用评分器的行，
  `valid` 为获得有限合法数值的行。`error/invalid/not_applicable/skipped_limit` 各自单列，
  五类数量相加等于该指标总样本数。预算外行也先校验输入，缺输入仍列为 invalid。
- 均值和中位数的分母只含该指标的 valid 行；空集为 JSON `null`。不能将错误当零，也不能只展示均值而隐去失败数量。
- scenario 和 risk 分组沿用相同口径。每个指标列出最低分的最多 10 行，含 question/reference/answer/分数/原因。
  RAGAS 当前薄适配仅提供指标结果原因码，不生成额外的解释性 LLM 请求。
- `judge_usage` 记录逐指标调用墙钟耗时；公开接口有 token usage 时记录 token，否则为 `null`。
  token 仅累加可观测用量，同时列出可得/缺失用量的调用次数，部分可得时不能视为完整消耗。
  墙钟耗时含指标内部调度和嵌入耗时，不能等同于单个 Judge HTTP 请求延迟。

score 只读取保存的采集文件，不重跑 Router、检索或 Generator。评分报告输出 JSON 及同名 Markdown，
包含安全 meta、逐行结果、failures、route_stats、分组、低分样本和用量。
上下文全文、history、sources 不复制进评分报告；问题、答案和 reference 保留便于复核。
采集文件含完整资料和历史，请按项目数据的访问边界管理。`logs/` 已被 `.gitignore` 忽略。

## Judge 配置与依赖边界

采集使用现有 `app.config.Settings`，CLI 显式 `Settings(_env_file=None)`，只取进程环境和默认值，
不读取任何 `.env*`。可通过进程环境指定 `ROUTER_MODEL`、`GENERATE_MODEL` 等现有配置。
Judge 使用独立 ScoreConfig/CLI 参数，例如生成模型 GLM-4-FlashX、Judge `glm-5.3-flash`。
分开模型和调用阶段便于更换 Judge、固定采集结果做比较，也减轻模型自评偏好；模型家族相同仍可能存在相关偏差。

Judge key 仅由 `--judge-key-env` 指定的环境变量读取，不接受明文 key 参数，也不写入 meta、日志或报告。
评分 URL 不写报告；SDK 异常不输出原文。已知 key 即使出现在回显内容中也会被替换为 `[REDACTED]`。
collect 同样按 Settings 的已知 LLM/重排 key 脱敏；不得把密钥主动放入问题、资料、参考答案或模型名。
日志脱敏仅临时给 eval/ragas 命名空间及其处理器添加 Filter，支持向上传播的新子 logger，退出时移除；
不替换全局 LogRecordFactory，不改写无关 logger 的日志。
CLI 配置错误与依赖缺失分别输出脱敏后的具体原因并退出 2；未知异常才使用不含 key 的泛化提示。

RAGAS 及 langchain-openai 仅在 score 默认后端初始化时导入；Web 运行时依赖不变。
评估依赖不放进 `backend/pyproject.toml` 和主 `uv.lock`（实测加入 ragas 会让 uv 把已有的 rich、websockets 降级并新增 22 个包），
而是放在独立的评估环境：依赖清单为 `backend/requirements-eval.txt`，环境目录 `backend/.venv-eval/`（已加入 .gitignore）。
`collect` 在主环境运行（需要模型与服务）；`score` 只读采集文件，在评估环境运行（只依赖 ragas 与 langchain-openai）。
安装与运行（在 `backend/` 目录）：

```bash
uv venv .venv-eval --python 3.11
uv pip install --python .venv-eval/bin/python -r requirements-eval.txt
.venv-eval/bin/python -m eval.ragas_eval score --in logs/ragas-collect-xxx.json --out logs/ragas-score-xxx.json --judge-model 模型名 --judge-base-url 地址 --judge-key-env 环境变量名
```

**Judge 配置的三种来源（优先级从高到低）**：命令行参数 → 环境变量 → `backend/.env`。
`.env` 里只会读取下面五个以 `JUDGE_` 开头的名字，其他任何变量（包括线上聊天使用的 `LLM_API_KEY`）一律不读取：

```text
JUDGE_API_KEY=评估专用密钥
JUDGE_MODEL=glm-5.3-flash
JUDGE_BASE_URL=与 LLM_BASE_URL 同一平台的 OpenAI 兼容地址
JUDGE_EMBEDDING_MODEL=（可选，仅回答相关度指标需要）
JUDGE_EMBEDDING_BASE_URL=（可选，不填则与 JUDGE_BASE_URL 相同时需显式填写）
JUDGE_EXTRA_BODY=（可选，JSON 对象，附加到每次 Judge 请求体）
```

**思考模式**：`glm-*` 模型有思考模式，思考内容会占用输出配额，导致 Judge 的 JSON 回答被截断而解析失败，并增加耗时与费用。
因此模型名以 `glm-` 开头且未设置 `JUDGE_EXTRA_BODY` 时，评估程序**默认附加** `{"thinking": {"type": "disabled"}}` 关闭思考；
其他模型默认不附加任何参数。需要自定义时显式设置，例如 `JUDGE_EXTRA_BODY={"thinking": {"type": "enabled"}}`，写 `{}` 表示不附加任何参数。

配置好后评分命令可以省略所有 Judge 参数：
`.venv-eval/bin/python -m eval.ragas_eval score --in logs/ragas-collect-xxx.json --out logs/ragas-score-xxx.json --metrics faithfulness,context_precision,context_recall`。
自定义的 `--judge-key-env 变量名` 只读环境变量，不会回落到 `.env`（避免借此读取其他密钥）。

**已知兼容问题（2026-10-19 实测）**：`ragas 0.4.3` 仍导入 `langchain_community.chat_models.vertexai`，而 `langchain-community 0.4` 已删除该模块，
直接安装会出现 `import ragas` 失败。`requirements-eval.txt` 因此加入 `langchain-community<0.4`（实测 0.3.31 可用）。
升级 ragas 后应先确认该限制是否仍需要，再放开。

安装得到真实版本后，用 `uv pip freeze --python .venv-eval/bin/python > requirements-eval.lock.txt` 固定版本。
未安装时清楚提示“需先安装评估依赖”。实际 RAGAS 版本尚未联网核验，安装后由总控核对
`backend/eval/ragas_backend.py` 的唯一入口 `make_scorer`，确认公开 API、指标列和 token usage 行为。
此适配使用单样本单指标 evaluate、关闭重试并传递超时；不通过结果中的 NaN 掩盖异常。

Response Relevancy 需要显式配置 embedding 模型与 OpenAI 兼容地址，避免悄悄采用默认外部服务。
当前 embedding 与 Judge 共用指定环境变量的 key；不同凭据/本地 embedding 可通过替身接口注入已包装对象。
后端可注入 `judge/embeddings`，编排可注入 `scorer(sample, metric)`，替身返回数值或
`{value, reason?, usage?}`；`status=error/invalid` 亦被保留。测试无需安装 ragas，无网络请求。

## 命令示例

在 `backend/` 下使用项目要求的 Python 3.11。以下命令是使用说明，本任务验收不执行真实服务或模型调用。
collect 需要已有的项目服务与模型；score 需要用户配置的 Judge/embedding 可用。
“离线”指与在线聊天请求分离、可保存重放，不表示真实评估模型必然运行于无网络环境。

```bash
python -m eval.ragas_eval collect \
  --eval-file data/eval_ragas_gold.jsonl \
  --out logs/ragas-collect-baseline.json

# 事先安全设置进程环境中的 RAGAS_JUDGE_KEY；命令行不填写 key。
python -m eval.ragas_eval score \
  --in logs/ragas-collect-baseline.json \
  --out logs/ragas-score-baseline.json \
  --judge-model glm-5.3-flash \
  --judge-base-url https://judge.example/v1 \
  --judge-key-env RAGAS_JUDGE_KEY \
  --max-samples 50 \
  --metrics faithfulness,response_relevancy,context_precision,context_recall \
  --embedding-model your-embedding-model \
  --embedding-base-url https://embedding.example/v1

# 仅核查证据支持程度时不需要 embedding。
python -m eval.ragas_eval score \
  --in logs/ragas-collect-baseline.json --out logs/ragas-score-faithfulness.json \
  --judge-model glm-5.3-flash --judge-base-url https://judge.example/v1 \
  --judge-key-env RAGAS_JUDGE_KEY --metrics faithfulness

python -m pytest tests/test_ragas_adapter.py tests/test_ragas_eval.py
```

## 已知局限

Judge 分数不是事实真值：Judge 会误判、受语言表达、提示注入、资料质量和模型偏好影响。
Faithfulness 可以奖励忠实复述错误资料；相关性高也可能漏答条件。应结合人工检查、路由/来源指标和错误分布解释。
当前按单轮原问评分，多轮省略、指代问题可能被低估，应结合采集 history 人工复核，不能把历史答案当作证据。
拒答/FAQ/cache/general 需要各自的规则与人工正确性检查，不适用计数不能解读为这些路径质量良好。
本实现不做并发评估、增量恢复或跨运行缓存；同一文件重打分会再次调用 Judge。
默认按顺序取前 N 行可能偏向前部场景，不能假定是无偏抽样。
小样本不看均值的小数点差异，不将不同有效分母直接比较；先检查 valid/错误/无效数量、场景覆盖、风险分布与低分题。
