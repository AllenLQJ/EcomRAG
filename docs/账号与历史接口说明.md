# 账号、配额与服务器历史接口

前端账号入口、聊天配额及历史功能使用以下接口。基础路径 `/api/v1`，请求与普通响应使用 JSON。成功体沿用已有接口的**直接对象**风格，没有额外的 `data` 或成功 `code` 包装；错误体统一包含 `code/message/request_id`，响应头含 `X-Request-ID`。以下 id、时间均为示例。

## 接口清单

| 方法和路径（以下省略 /api/v1） | 请求体 | 成功状态及响应 |
| --- | --- | --- |
| POST /auth/register | `{ "username":"Alice_01", "password":"A-unique-password!" }` | 201，`{"user":{"id":1,"username":"Alice_01"}}`，设置新会话 Cookie |
| POST /auth/login | 同注册 | 200，同注册成功体，更换会话令牌并撤销本次请求携带的旧令牌 |
| POST /auth/logout | 可省略 | 200，`{}`，撤销当前令牌并清会话 Cookie；无 Cookie 时也成功 |
| GET /auth/me | 无 | 200，返回用户或 null 及当日配额，仅读取、不增加计数 |
| DELETE /auth/account | `{"password":"A-unique-password!"}` | 200，`{}`，删除账号、全部历史，撤销该用户全部会话并清 Cookie |
| GET /conversations | 无 | 200，`{"items":[{"id":"0123456789abcdef0123456789abcdef","title":"订单问题","updated_at":"2026-10-19T08:00:00+00:00","message_count":2}]}` |
| POST /conversations | `{}` 或 `{"title":"订单问题"}`；可省略请求体 | 201，`{"id":"0123456789abcdef0123456789abcdef","title":"订单问题","updated_at":"2026-10-19T08:00:00+00:00","message_count":0}` |
| GET /conversations/{id} | 无 | 200，见下方详情样例 |
| PATCH /conversations/{id} | `{"title":"新标题"}` | 200，返回与列表项相同的对象 |
| DELETE /conversations/{id} | 无 | 200，`{}`，硬删除对话及消息 |

用户名为 3–20 位 ASCII 字母、数字、下划线，按小写规范值唯一，展示保留注册时原样。密码 8–64 个字符，不能与用户名相同（不区分大小写）、不能为纯数字、不能是内置常见弱口令。注册规则错误返回可直接展示的中文原因；重复用户名返回“用户名已被使用”。登录不存在的账号返回 HTTP 401 / `40102`“账号不存在”；已存在账号密码不匹配返回 HTTP 401 / `40103`“密码错误”。两种失败均执行一次 scrypt 校验和 `hmac.compare_digest`。这是产品负责人明确要求的可区分反馈，已接受账号枚举风险；假哈希只减少计算耗时差异，不隐藏账号是否存在。内置假哈希首次使用时惰性初始化，真实和不存在账号共用该初始化过程。

注册、登录、注销账号的所有口令入口统一最多 64 个字符，超长直接返回 400/40003“密码长度须为8–64位”，不会创建假哈希或执行密码哈希；HTTP 模型、服务方法和哈希函数均有检查。登录/删号的短错误口令仍返回认证失败，不使用注册的强度规则。`/auth/logout` 不接受也不校验口令，只撤销当前会话。

错误码及前端反馈（均保留 `request_id`）：

| HTTP / code | 原因与前端文案 |
| --- | --- |
| 400 / 40001 | 其他请求参数非法 |
| 400 / 40002 | 用户名不合规：3–20 位字母、数字或下划线 |
| 400 / 40003 | 密码不合规：8–64 位；与用户名相同、纯数字或常见弱口令分别返回具体中文原因 |
| 401 / 40101 | 未登录或会话失效，请重新登录 |
| 401 / 40102 | 账号不存在（登录） |
| 401 / 40103 | 密码错误（登录或注销密码校验） |
| 403 / 40301 | 请求来源校验失败；前端显示“访问来源未被允许，请使用正确的访问地址。” |
| 409 / 40901 | 用户名已被使用（不区分大小写） |
| 429 / 42903 | 请求过多或账号锁定；返回具体原因、`retry_after_seconds` 和 `Retry-After`，前端倒计时后允许重试 |
| 503 / 50301 | 账号存储服务暂不可用 |

注册格式错误保留输入框旁可见提示；服务端返回的密码强度和限流中文原因优先展示，无具体原因时按错误码显示中文文案。入口页和侧栏登录弹窗共用品牌、卡片和表单（墨印 logo、字标、标语、页签、黑色主按钮），仅入口页提供“以访客进入”。注册页不再显示顶部演示密码提示条。

游客历史仍按原逻辑保存于当前浏览器，可以逐条删除；侧栏已移除“清空全部历史”及本地存储说明区块，因此界面不再提供一键清空本地历史的入口。账号/游客历史隔离和游客历史持久化不变。“店铺信息”入口位于新对话空会话主区域顶部（欢迎语和推荐问题之前），点击打开现有店铺信息弹窗，侧栏底部不再提供该入口。

`GET /auth/me` 的账号样例：

```json
{
  "user": {"id": 1, "username": "Alice_01"},
  "quota": {
    "role": "user", "limit": 50, "used": 2, "remaining": 48,
    "resets_at": "2026-10-20T00:00:00+08:00"
  }
}
```

游客返回 `"user":null`、`"role":"guest"`、默认 `"limit":5`。登录不迁移或清除游客计数，登出后继续受原游客/IP 配额限制。

对话详情样例：

```json
{
  "id": "0123456789abcdef0123456789abcdef",
  "title": "订单问题",
  "messages": [
    {"role":"user","content":"如何查询物流？","route":null,"sources":null,"created_at":"2026-10-19T08:00:00+00:00"},
    {"role":"assistant","content":"可以在订单页面查看物流。","route":"faq","sources":[{"index":1,"doc_id":"faq:1","title":"物流查询","snippet":"可以在订单页面查看物流。","score":1.0}],"created_at":"2026-10-19T08:00:01+00:00"}
  ]
}
```

列表按 `updated_at` 倒序，最多 100 条；每用户最多 100 个对话，创建使用用户行锁避免并发越限。标题最多 100 字，可为空。详情取最近 200 条消息，按时间、消息 id 正序返回。所有带 id 的访问先检查 `id + user_id`，其他人的 id 与不存在的 id 均为 404/40401“对话不存在”。历史接口必须登录。

## 聊天自动保存

`POST /api/v1/chat` 与 `POST /api/v1/chat/stream` 均接受新增可选字段：

```json
{"session_id":"client-session","message":"如何查询物流？","history":[],"conversation_id":"0123456789abcdef0123456789abcdef"}
```

游客携带的 `conversation_id` 被忽略。登录用户携带时先验证归属，错误在启动 SSE 之前返回 HTTP 404；通过配额和分钟限流后先保存用户问题，成功回答后保存助手最终答案、route 以及仅含 index/doc_id/title/snippet/score 的 sources。每条正文最多保存 4000 字，响应正文不被截断。空标题用问题前 20 字生成，写入消息和改标题均更新 `updated_at`。任何保存失败仅记录固定脱敏告警，不改变聊天结果；无法验证归属的数据库故障仍返回 503，避免绕过权限检查。

服务器历史额外执行以下固定写入上限（服务层和仓库层均生效）：

- 正文最多 4000 字符，route 最多 16 字符；单条消息的 role/content/route/sources 紧凑 JSON（UTF-8 编码，包含转义开销）最多 32 KiB，超出则拒绝该条保存，聊天回答不受影响。
- sources 最多 8 项，紧凑 UTF-8 JSON 总计最多 8 KiB；每项仅保留既定五个字段，doc_id/title/snippet 分别最多 128/200/500 字符。字段截断，超出条数/总字节预算的引用丢弃；无效索引或非有限分数不落库，不先整体遍历或序列化无界 sources。
- 每个对话在数据库实际只保留最近 200 条消息。写入和清理旧消息在同一事务、同一对话行锁下完成，避免并发写入越过上限；更旧消息被硬删除，message_count 表示保留条数。此规则不同于仅在读取时 LIMIT 200，用户需要保留更早内容时应在被清理前导出。

普通接口回答成功后保存助手消息；流式接口在 `done` 事件成功发送、生成器继续执行时保存。模型错误、流中错误和完成前取消不保存助手消息，因此历史可能只剩用户消息。服务器历史不会自动注入模型上下文，现有请求 `history` 的含义保持原样。

流式响应保留已有契约：HTTP 200 之后的限流/模型失败用 SSE `error` 事件结束，客户端必须检查事件中的业务码；不会在已发送 `meta` 后修改 HTTP 状态。例如：

```text
event: error
data: {"code":42902,"message":"游客每天可提问5次，今天已用完，登录后每天可提问50次","request_id":"example-request-id","limit_scope":"guest"}
```

## Cookie、CSRF 和 CORS

- 会话 Cookie `ecomrag_session`：32 字节随机值的 urlsafe 编码，HttpOnly、SameSite=Lax、Path=/、Max-Age=604800（7 天）。登录每次生成新值，Redis 仅保存令牌的 SHA-256，不保存原令牌。退出和注销使用相同 Path 和安全属性清除。
- 游客 Cookie `ecomrag_guest`：随机标识附 HMAC-SHA256 签名，具有同样 Cookie 属性和有效期；修改或伪造后会重新签发。首次访问 `/api/v1/*` 时发放，包含错误响应。
- 请求为 HTTPS 时设置 Secure。只在 `TRUST_PROXY_HEADERS=true` 且连接对端命中 `TRUSTED_PROXIES` 时接受 `X-Forwarded-Proto: https`。真实 IP 沿用现有 `CLIENT_IP_HEADER` 和可信代理判断。
- 所有账号/历史 POST、PATCH、DELETE 必须携带 `X-Requested-With: ecomrag`，缺失或值不符返回 403/40301。账号/历史请求带 Origin 时，允许 `CORS_ORIGINS` 显式白名单或与请求原始 `Host` 的 host:port 一致的来源；其他来源返回 40301。无 Origin 的非浏览器调用仍需上述修改请求头。
- 两个聊天 POST 接口也检查 Origin：带 Origin 且既不在白名单、也不匹配原始 Host（包括 `null`）时，在认证、配额、模型或历史写入之前返回 403/40301。选择校验浏览器已有的 Origin，而不新增必须的 X-Requested-With，以保持现有前端和无 Origin 的非浏览器调用兼容。SameSite=Lax 与 CORS 响应头本身不能阻止同站恶意子域消耗配额，因此来源检查在服务端副作用之前执行。客户端无需新增请求字段；不能把不可信同站子域列入允许来源。
- 反代同源判断：`Origin: http://127.0.0.1:8080` 与 `Host: 127.0.0.1:8080` 可直接访问，无需新增白名单；8010 与 8080 端口不同则拒绝。仅接受 HTTP(S) Origin，拒绝凭据、路径、查询、片段、歧义重复头和非法端口，主机名大小写归一，支持 IPv6；隐式端口按 Origin 的 scheme 取 HTTP 80 / HTTPS 443。
- **scheme 取舍与风险**：Caddy 终止 TLS 后，后端 ASGI scheme 可能始终为 HTTP；当前部署关闭代理头信任，无法据此可靠恢复浏览器 scheme。因此 Host 匹配采用 host:port 比较（按 Origin scheme 归一默认端口），不强制与内部 scheme 一致。这允许相同 host:port 的 HTTP/HTTPS 来源，无法将跨 scheme 请求作为拒绝边界；生产环境应在可信边缘强制 HTTPS，并限制可访问的站点 Host。该校验不使用 `X-Forwarded-Host`、`X-Forwarded-Proto` 或 `Forwarded`，即使设置 `TRUST_PROXY_HEADERS=true` 也不能用转发头覆盖原始 Host；`false` 时 Cookie Secure 和真实 IP 判断同样不信任转发头。
- **Host 信任边界**：浏览器脚本不能随意覆盖 Host，Origin 与 Host 不一致（含只伪造 Host 或转发头）的跨站请求会被拒绝。能同时伪造匹配 Host 和 Origin 的非浏览器客户端不在此 CSRF 防护保证内，且本来允许无 Origin；本校验不是域名白名单或认证替代。反代必须保留合法外部 Host，公网部署应由 Caddy 的站点配置约束 Host，避免把任意域名/不可信子域转发到同一应用。
- CORS 开启 `allow_credentials`，允许 GET/POST/PATCH/DELETE、Content-Type、X-Requested-With，禁止通配来源 `*`。浏览器跨来源调用需设置 `credentials: "include"`；跨站 Cookie 仍受浏览器 SameSite=Lax 规则限制，应采用同站部署。

## 配置与计数

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| GUEST_DAILY_LIMIT | 5 | 游客标识和可信 IP 两个维度取更严格计数，即使关闭旧分钟 IP 限制仍启用游客 IP 日配额 |
| USER_DAILY_LIMIT | 50 | 账号按 user_id 跨浏览器会话累计 |
| RATE_LIMIT_DAY_TZ_OFFSET_HOURS | 8 | 固定时区偏移，自然日零点重置，不采用夏令时 |
| RATE_LIMIT_PER_DAY | 200 | 保留旧 IP/session 的 UTC 自然日兜底上限；与默认 +8 角色配额的重置时间不同 |
| RATE_LIMIT_PER_MIN | 50 | 旧 IP/session 分钟限制及 RATE_LIMIT_IP_ENABLED 行为保留 |
| AUTH_SECRET | 空 | DEBUG=false（默认，非开发模式）时空值/全空格导致启动 ValueError；所有 worker 必须配置同一持久随机密钥，建议至少 32 字节随机值。仅 DEBUG=true 开发模式允许进程随机值并告警其不支持多 worker |
| AUTH_SCRYPT_N | 32768 | 2 的幂，32768–262144；r=8、p=1、盐16字节、输出32字节，需按实际机器校准耗时 |
| AUTH_IO_WORKERS / AUTH_IO_MAX_IN_FLIGHT | 4 / 16 | 独立有界线程池，运行密码哈希、账号 SQL/Redis；配额使用独立 rate-limit 容量配置 |

配额在现有 `before_chat` 检查阶段执行，FAQ/缓存命中也计数；被限流或随后模型失败的尝试同样计数，`used` 可大于 limit，remaining 最小为 0。角色日配额优先判定，因此账号达到 50 次且同时命中旧分钟上限时仍得到 42902/user。`/auth/me` 不增加计数；`resets_at` 是所配置时区的下一个零点 ISO8601 时间。

为保留已有限流窗口，旧兜底固定在 UTC 00:00（北京时间 08:00）重置，新角色配额默认在北京时间 00:00 重置；两者独立。`/auth/me.quota` 及 resets_at 只描述新角色配额，即使其剩余次数大于零，仍可能被尚未重置的旧兜底限制；旧兜底错误不附角色 limit_scope。调整 RATE_LIMIT_DAY_TZ_OFFSET_HOURS 仅影响新配额，不修改旧窗口。

防暴力破解：注册和登录共用 IP 20 次/滚动 10 分钟限制；仅为已存在账号按 user_id 记录连续失败，5 次错误后锁定 15 分钟，第 5 次及锁定期间返回 42903，成功登录清除连续失败。不存在的用户名仍执行假哈希比较并返回 401/40102“账号不存在”，但不读写账号锁定计数，注册后不会继承此前同名猜测；已存在账号锁定时与未知用户名的响应会不同，不能据此宣称完全无法枚举账号。注销密码校验也使用已存在账号的锁定，避免绕过登录保护。Redis 原子事务/Lua 维护计数；进程保留同步镜像，Redis 故障时使用本进程计数且限频告警，不会无限放行；本地安全计数容量满时返回 50302，不逐出有效锁定。

Redis 不可用时注册/登录仍返回 50301，绝不在本地建立账号会话。会话查询失败则降级为游客（含任意会话形、过期或曾有效的 Cookie），只授予游客配额，忽略 conversation_id，不写入账号历史；`/auth/me` 返回 user:null，历史和删号接口返回 401/40101。Cookie 不会让请求直接获得账号权限，也不能跳过游客/IP 限制；Redis 恢复后会重新校验保留的 Cookie。已有账号经此路径聊天会按匿名 chat_logs 策略记录，客户端如需账号私密历史应等待会话服务恢复。登出仍需要真正撤销 Redis 会话，Redis 故障时返回 50301，不会假报撤销成功。

Redis 主要 key：`auth:session:<sha256(token)> → user_id`，7 天 TTL；附属 `auth:session_guard:<sha256(token)>` 保存 AUTH_SECRET 计算的签名，使临时密钥重启或密钥更换后旧会话失效；`auth:user_sessions:<user_id>` 索引用于注销全部令牌；`auth:attempt:*` 为滚动 IP 尝试窗口，`auth:failure:user:<sha256(user_id)>` 为账号连续失败/锁定；`chat:quota:*` 是角色日计数，TTL 到对应零点。所有计数身份维度均用哈希键，避免原始 IP/游客标识出现在计数 key 中。新账号锁定使用独立 user 命名空间，旧版按用户名的 failure key 不再使用，可由运维单独清理，不能据此锁定新注册账号（包括纯数字用户名与 user_id 同值的情况）。

## 数据表与隐私删除

`python -m ingest.migrate_db` 在既有 chat_logs 补列后，通过 CREATE TABLE IF NOT EXISTS 幂等创建以下 MySQL 8.0.13+ InnoDB 表；启动不会自动创建账号表。

迁移局限：账号/历史部分只创建缺失表，不检查或修复已存在表的列类型、唯一索引、普通索引、外键或级联行为；重复运行成功不代表已有表结构已正确升级。上线前必须核对实际 SHOW CREATE TABLE，并为旧结构另写经审核的数据/DDL 迁移。应用层写入上限不会自动清洗所有存量数据：超过 200 条的旧对话在下次写入时裁剪，存量超大正文/sources 需要单独清理；直接 SQL 写入也不受应用预算保护。

| 表 | 字段及约束 |
| --- | --- |
| users | id BIGINT 自增主键；username_norm VARCHAR(20) ASCII 二进制排序且 UNIQUE；username_display VARCHAR(20)；password_hash VARCHAR(255)；created_at、last_login_at UTC DATETIME(6)；status TINYINT，1 表示启用 |
| conversations | id CHAR(32) uuid4 hex 主键；user_id BIGINT；title VARCHAR(100)；created_at、updated_at UTC DATETIME(6)；(user_id,updated_at) 索引；user_id 外键 ON DELETE CASCADE |
| messages | id BIGINT 自增主键；conversation_id CHAR(32)；role ENUM('user','assistant')；content TEXT；route VARCHAR(16) NULL；sources JSON NULL；created_at UTC DATETIME(6)；(conversation_id,created_at,id) 索引；conversation_id 外键 ON DELETE CASCADE |

SQL 值全部参数化。密码存储格式为 `scrypt$n$r$p$salt_b64$hash_b64`。密码与原会话令牌不进入业务响应正文、日志、异常栈原文、trace 或 chat_logs（Cookie 自然包含客户端所需令牌，Redis key 只使用其哈希）。请求日志只记录方法、路径、状态、耗时和 request_id，不记录 auth 请求体、Cookie 或请求头。

成功认证用户的消息正文属于隐私数据，只写服务器历史，不复制到旧匿名 chat_logs；只有 user is not None 时才跳过该日志，无效 Cookie 或 Redis 降级不能逃避匿名记录策略。日志文件和 trace 仅含元数据，保存失败不打印正文、sources、密码或数据库异常文本。通过 DELETE /conversations/{id} 可以彻底删除该对话与全部消息；通过 DELETE /auth/account 可彻底删除账号、全部对话与消息并撤销全部会话令牌。匿名 chat_logs（含无法认证而降级的聊天）、数据库备份或基础设施日志由原有运维保留策略管理，不属于账号历史的删除范围。

## 已知局限与真实环境验收

游客识别可以通过清除 Cookie 重置游客标识，IP 维度仍会限制同一 IP，但同时换 IP 可绕过；共享出口会共享游客配额。真实 IP 维度依赖可信入口覆盖/清洗来源头和正确透传，目前部署尚未完成。Redis 故障时计数退化为单进程，跨 worker 无法严格共享；进程重启也会丢失降级计数。MySQL 与 Redis 不存在分布式事务：注册建立会话失败会补偿删除新用户；极端连接故障时补偿可能失败，客户端重试可能遇到用户名占用。会话签发与注销在同一 MySQL 用户行锁下串行化；注销先撤销会话再删除账号，迟到登录必须重新确认用户仍存在。若数据库提交失败，已撤销会话不会恢复，用户需重新登录；真实环境仍需验收并发及故障恢复。

已在 backend/ 尝试 `uv run --offline --no-sync python -m pytest`：默认缓存和受管 Python 目录读取被权限策略拒绝；改用工作区缓存、仅系统解释器且禁止下载后，明确报错找不到 Python 3.11。当前可用系统 Python 是 3.9、hashlib 未提供 scrypt，且未安装 FastAPI/pytest；直接执行 python3 -m pytest 也因缺少模块失败。因此未运行完整单元测试，不声称回归通过。不启动真实 MySQL/Redis/模型/服务，不读取或修改任何 .env 文件。测试使用替身仓库、脚本化 MySQL 连接和 fake Redis。语法检查和标准库隔离自检不等同于 pytest、真实密码哈希或 HTTP 回归测试，真实 MySQL 级联和并发裁剪均尚未验证。
