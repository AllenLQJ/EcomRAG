# 图谱在线化设计（10 万商品 / 多并发）

本文是 `docs/电商RAG智能客服-开发文档.md` 2.2 节「知识图谱」的扩展设计，描述商品规模到 10 万、并发上来之后，「是否走并行图谱」及查询后的处理流程。**标注「已实现」的内容已合入 main；其余为拟定方案，尚未实现。**

## 1. 目标与约束

- 规模假设：商品约 10 万，同时在线请求为多并发；当前演示数据约 50 个商品。
- 图谱不能拖慢或拖垮主链路：任何异常、超时、满载都退回纯 RAG，不返回 5xx。
- 只读白名单 Cypher，用户输入只进参数；兼容结论必须带「规格层面」免责句。
- 不做：自由 Text2Cypher、第二套文档向量库、整仓图谱产品化。

## 2. 现状（已实现）

| 项 | 现状 |
| --- | --- |
| 接入方式 | knowledge 路由后与向量检索并行；命中时作为资料 [1]；检索低分时只用图谱资料回答，生成器仍可输出 NO_ANSWER |
| 是否查图谱 | `planner.py` 规则：实体链接 + 关键词意图 + 具体模板；供电类关键词需有另一端（第二实体、供电商品、找供电端问法或「哪些」汇总） |
| 并发隔离 | 独立线程池 `GRAPH_WORKERS`（默认 4，不排队），池满跳过；多条查询串行，累计超 `GRAPH_TIMEOUT_S` 放弃剩余 |
| 结果控制 | 模板按结论排序（规格匹配 → 部分匹配 → 不匹配），在线 `LIMIT 21`，资料最多 20 行、`GRAPH_MAX_CHARS` 字 |
| 实体别名 | 进程内存字典，启动后首次查询时全量加载，逐条正则匹配 |
| 数据导入 | `ingest.graph_load` 单事务 `DETACH DELETE` 后全量重建 |
| 缺失 | 无缓存、无熔断、无版本号、无图谱专项监控 |

## 3. 现状的问题

1. **关键词判断太局限**：评测集是照规则生成的，仍有 5/94 题被门槛拦下；口语问法漏判会更多，误判只能靠补丁修。
2. **10 万商品下的成本**：别名表逐条正则匹配会变慢；汇总类模板（如「哪些商品不需要充电器」）无过滤会扫全图。
3. **并发下的失控风险**：Neo4j 变慢时每个请求都要等满超时；同样的问题反复查库。
4. **导入不适合线上**：清空重建期间无法增量更新，10 万节点单事务过重。

## 4. 目标流程

```
FAQ / 缓存未命中
 → LLM 路由（同一次调用）输出 intent、rewritten_query、graph_type
 → knowledge：
     ├─ 向量检索 + 重排（不变）
     └─ 图谱分支（并行，总时限 GRAPH_TIMEOUT_S，失败即跳过）
          熔断打开或 graph_type 为空 → 不查
          实体链接（Aho-Corasick）；无实体且无过滤条件 → 不查
          按 graph_type 选白名单模板 → Redis 缓存 → Neo4j 只读副本（async 并行）
 → 合并：图谱资料 [1] + 向量资料 → 带引用生成 → 免责句校验
```

## 5. 设计

### 5.1 查不查图谱：路由输出 `graph_type`

- `RouteDecision` 新增可选字段 `graph_type`，枚举：`power / signal / storage / package / multi / scene / null`，缺省 `null`。契约为 `extra="forbid"` 且严格校验，需同步改 `contracts.py`、`router.md` 提示词与示例；旧提示词不输出该字段时按 `null` 处理。
- 路由只回答「是哪类关系问题」，**不选具体模板、不填 id**；具体模板由规则按 `graph_type` + 已链接实体选定。
- 路由 JSON 解析失败走原兜底路径时，`graph_type` 退回现有关键词规则（`planner.detect_intent`），规则只作兜底。
- 路由为 `general` / `sensitive` 时不查图谱（现有行为不变）。
- 判断宁宽勿严：图谱是并行、有线程池与时限限制的，误查最多多一段无关资料，不会答错。

### 5.2 实体链接

- 别名表换成 Aho-Corasick 自动机（需评估是否引入 `pyahocorasick` 依赖，或自行实现），匹配耗时与商品数无关，毫秒级。
- 自动机在后台按图谱版本号构建，构建完成后原子替换；构建期间继续使用旧版本。
- 保留现有规则：单独型号（如「L1」）不作别名，「系列 + 后续型号」继承，外部设备与场景词匹配。
- 路由要求查询、但没有链接到任何实体时，可选地用商品名向量做一次模糊匹配（处理简称、错别字）；作为第二期，不进首批。

### 5.3 查询

- 改用 neo4j async driver，同一问题的多条查询并行，总时限仍为 `GRAPH_TIMEOUT_S`；现有线程池在迁移完成前保留。
- 索引：`id`（已有唯一约束）、`category`、`series`；推导边（供电、兼容）继续离线预计算，线上不做现场推理。
- **汇总类模板必须带过滤条件**（品类或系列），否则不查；不带过滤的全量汇总在 10 万商品下不可接受。
- 查询结果缓存：Redis，key 为「模板名 + 参数哈希 + 图谱版本」，TTL 由 `GRAPH_CACHE_TTL_S` 控制；缓存读写失败按未命中处理。

### 5.4 降级与熔断

- 保持现有：线程池满、超时、报错 → 记录 `graph_unavailable`，按纯 RAG 回答。
- 新增熔断：滑动窗口内连续超时/报错达到阈值后，在冷却期内直接跳过图谱，不再发起查询；冷却结束后放行少量探测请求，成功则关闭熔断。

### 5.5 合并与生成

- 图谱命中时，向量资料 `top_k` 由 5 降为 3，使总上下文基本不变（`GRAPH_TOPK_WITH_GRAPH`）。
- 向量低分或无结果但图谱命中：只用图谱资料生成；生成器输出 NO_ANSWER 时仍然拒答（已有测试）。
- 免责句：结论含「匹配」时，生成后校验回答是否包含 `CAVEAT`，缺失则补在末尾；不再只依赖提示词约束。
- 图谱资料在重排之后加入，不经过远程重排。

### 5.6 数据更新

- 导入由「清空重建」改为按 `id` 分批 `MERGE` 增量更新，每次更新递增图谱版本号（存放在 Neo4j 元数据节点和 Redis）。
- 版本号变化即让查询缓存与实体自动机失效。
- 删除商品走显式下架清单，不用清空代替。

### 5.7 监控

| 指标 | 用途 |
| --- | --- |
| 图谱触发率 / 命中率 | 判断 `graph_type` 是否过宽或过窄 |
| P50 / P95 查询延迟、超时率 | 容量与索引问题 |
| 缓存命中率、熔断次数 | 并发与稳定性 |
| 图谱参与回答后的 NO_ANSWER 率、免责句补全率 | 回答质量 |
| 线程池拒绝数 | `GRAPH_WORKERS` 是否够用 |

均写入现有 trace 的 `graph` 阶段与日志，不新增存储。

## 6. 新增配置（拟定）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| GRAPH_CACHE_TTL_S | 600 | 查询缓存 TTL；0 表示关闭 |
| GRAPH_BREAKER_FAILURES | 5 | 触发熔断的连续失败次数 |
| GRAPH_BREAKER_COOLDOWN_S | 30 | 熔断冷却时间 |
| GRAPH_TOPK_WITH_GRAPH | 3 | 图谱命中时向量资料保留条数 |

## 7. 评测与测试

- **口语化题集**：50–100 条口语化关系题，加一批链接到商品但不问关系的非关系题，作为路由 `graph_type` 的准确率评测集；先于任何实现，用来量化现有规则的漏判率与误判率。
- **评测口径**：`run_eval` 的来源命中只认商品页，需把 `graph:*` 计入命中，另加「免责句出现率」；回答质量按期望商品名与关键数字评分。
- **单测**：`graph_type` 缺省与非法值、规则兜底、熔断状态机、缓存键与失效、增量导入幂等、汇总无过滤不查。
- **压测**：Neo4j 变慢与不可用两种场景，确认延迟增量有上限、线程池与模型调用互不影响。

## 8. 分期

1. 口语化题集，量化现状。
2. 路由 `graph_type`，规则降为兜底。
3. 熔断、查询缓存、async 并行查询。
4. Aho-Corasick 实体链接、增量导入与版本号、汇总模板必带过滤。
5. 按需：模糊实体匹配、监控面板。

前两期解决「判断太局限」；第 3、4 期在数据量和并发实际上来后再做，各期上线前重跑图谱评测集，召回与回答质量不得下降。

## 9. 风险

| 风险 | 缓解 |
| --- | --- |
| 路由提示词变长，影响原有三分类准确率 | 变更后重跑主评测集与路由评测；`graph_type` 缺省 `null` |
| 路由误判导致无关资料干扰回答 | 规则那一关仍要求链接到实体并命中模板；监控 NO_ANSWER 率 |
| 缓存导致更新后读到旧结果 | 缓存键含图谱版本号 |
| 熔断参数不当导致图谱长期不可用 | 冷却后探测恢复；熔断次数纳入监控 |
| 自动机重建内存峰值 | 后台构建、原子替换，构建失败保留旧版本 |
