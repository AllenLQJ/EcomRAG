# 商品卡片接口说明

## 对外契约

适用于 `POST /api/v1/chat` 的 JSON 响应，以及 `POST /api/v1/chat/stream` 的 SSE `done` 事件。两个入口复用同一 pipeline、查询和序列化逻辑。请求不增加参数，已有 `answer`、`route`、`sources` 等字段保持原义。

仅成功的 `route="rag"` 回答，且其最终 `sources` 能关联到有效商品时，增加顶层 `products`。它不是新的 SSE 事件，不出现在 `meta`、`status`、`delta` 或 `error` 中。FAQ、Redis FAQ 缓存、闲聊、敏感拒答、低分拒答、`NO_ANSWER` 和其他兜底均不返回该字段。

| 字段 | JSON 类型 | 约束 / 含义 |
| --- | --- | --- |
| `products` | array of object，可缺省 | 有值时 1–3 项；无卡片时整个字段缺省，不输出 `null` 或空数组 |
| `products[].sku` | string | 商品表 `sku_id`，前端的稳定商品标识 |
| `products[].name` | string | 商品表名称；不从答案或文档标题生成 |
| `products[].category` | string | 商品表中文品类，例如 `桌面台灯`，不同于知识库的 `product` 分类 |
| `products[].highlights` | string[] | 1–2 条 `规格名：规格值`，只取商品表 `specs` 的规格白名单 |
| `products[].image_url` | string 或 null | 完整 HTTP(S) 地址，或未配置基础地址时的相对路径；非法或缺失的库内图片路径返回 null |

示例（其余原有字段省略）：

```json
{
  "route": "rag",
  "answer": "栖光 L1 的额定功率为 6 瓦。[1]",
  "products": [
    {
      "sku": "qiguang-l1",
      "name": "栖光 L1 桌面台灯",
      "category": "桌面台灯",
      "highlights": ["额定功率：6 瓦", "色温档位：3000、4000、5000 开尔文"],
      "image_url": "https://images.example.com/products/qiguang-l1/main.webp"
    }
  ]
}
```

旧前端可以继续忽略未知字段。新前端以 `products` 是否存在决定是否展示卡片，处理 `image_url=null`；不要从卡片反推答案引用编号，引用编号仍以 `sources[].index` 为准。一份指南可以关联多个商品，一张卡片也可能由多份来源共同关联。卡片表示引用资料关联的商品，不表示答案逐项推荐了所有商品。

## SKU 解析、选择与排序

只处理 pipeline 生成最终 `sources` 对应的检索文档，不使用全部检索候选，不识别用户输入或模型答案中的 SKU，也不扫描正文里的对照型号。沿用现有引用校验：优先取答案文本内有效引用；完全没有有效引用时，现有 pipeline 将最高分文档作为来源，卡片遵循同一规则。

每个来源按以下优先级解析，前一级存在时不与后一级合并：

1. 检索 `RetrievedDoc.skus` 元数据。`null` / 缺失表示旧索引没有元数据，继续回退；显式 `[]` 表示不关联商品，停止回退。该元数据不加入对外 `sources`。
2. 配置的 `manifest.csv` 中 `file → skus` 映射。支持分号、逗号、竖线、中英文分隔符与空白。匹配规范化来源路径，必要时匹配文件名，兼容 `content_merge` 的扁平暂存目录。同名映射不一致时不猜测；空 `skus` 也明确表示无商品。
3. 单品文件名 `product_<sku>.md`。四个旧文件名 `product_tinglan_s1.md`、`product_tinglan_s2.md`、`product_qiguang_l1.md`、`product_muche_c1.md` 有显式下划线兼容。目录页 `product_catalog.md`、指南 `product_guide_*.md` 不凭文件名匹配商品，需 manifest 或元数据。

SKU 区分大小写，只接受最长 64 字符的小写字母、数字及单连字符。无效项丢弃，按原顺序去重。

按最终 `sources` 的顺序（生成上下文编号顺序，并非答案中首次提及顺序）遍历，每个来源内按 `skus` 原顺序遍历，跨来源再次去重。最多查询前 100 个候选；商品缺失、隐藏或数据不合格时跳过并从后续候选补齐，最多输出 3 项。不重新按 MySQL 返回顺序、名称或价格排序。

## 商品表、下架与数据边界

使用现有 MySQL `products` 表，不修改表结构、CSV 或商品导入语义。每次只批量查询 `sku_id, name, category, specs, image_main`，参数化 `IN` 查询；不存在的 SKU 直接跳过。不会读 CSV 作为在线数据兜底，以免重新展示数据库中已删除的商品。

现有表没有上下架字段，因此本实现明确约定：

- 表中删除的商品视为不可展示；数据库删除在下次查询立即生效。
- 逻辑下架由配置 `PRODUCT_HIDDEN_SKUS` 指定，例如进程环境 JSON 数组 `["tinglan-s1"]`。更新应用配置并重启后生效。隐藏判断先于数据库查询；元数据和 manifest 都不能绕过它。
- 没有新增或假定 `status`、`enabled`、库存字段。如果今后需要业务后台直接上下架，应另行增加状态列、迁移及查询过滤；本次不将未知状态字段解释为在售。

卡片是严格白名单 DTO，无价格、库存、定位长文、包装或营销字段。规格按品类固定优先级提取最多两条，例如台灯优先“额定功率、色温档位、亮度调节”，耳机优先“佩戴方式、关闭主动降噪单次续航、单次音乐续航、降噪能力、续航说明”。名称及规格值额外过滤常见价格、促销、库存词与货币标记；规格值限制为 200 字符。未知品类、规格 JSON 无效或没有任何合格规格时跳过该商品。不会把 `specs` 原对象或 SQL 原行透传给前端。

数据库故障、表尚未建立、manifest 读取失败、卡片超时等仅降级为省略 `products`，保留已生成答案；日志只记录 `product_cards_unavailable`，不包含数据库异常正文、凭据或商品原文。已有整请求超时和客户端取消语义不变。

## 图片约定与配置

已核对 `ingest.products`、`load_products`、`migrate_products` 和现有 SQL：`image_main` 只存 `<sku>/main.webp` 等相对路径。图片不写回数据库为完整 URL。

- 原图：`data/images_src/<sku>/main.png`，`images-build` 也接受 PNG/JPG/JPEG/WebP，优先选择名为 `main` 的文件。
- 构建产物：`data/images/<sku>/main.webp`（最长宽度 800）、`thumb.webp`（最长宽度 320），保持宽高比，透明区域合成浅色背景。
- 缺图：`main.svg` 与 `main.placeholder`。构建真图成功后删除 `main.placeholder`；即使旧 SVG 仍在，也不再使用占位图。
- 卡片沿用库内 `image_main`，本机同 SKU 下存在占位标记和 SVG 时改用 `<sku>/main.svg`。运行时不做图片转换，也不从原图目录返回地址。
- 库内路径只接受同 SKU 下的 `main.webp/png/jpg/jpeg/svg`；外站地址、跨 SKU 路径、查询参数和路径穿越均返回 null。

`IMAGE_BASE_URL` 默认空。配置为图片根目录的公开 HTTP(S) 前缀，例如 `https://images.example.com/products`，将得到 `https://images.example.com/products/<sku>/main.webp`；前缀允许路径，会统一去掉结尾 `/`。禁止凭据、查询串、片段及非 HTTP(S) 协议。

为空时，返回 `qiguang-l1/main.webp` 或占位图相对路径，不添加前导 `/`；库内图片路径无效或为空时返回 null。前端需要按部署的图片根地址解析该相对路径，不应直接按聊天 API URL 拼接。

本次不增加静态图片服务。部署方需让反向代理、对象存储或现有静态服务托管 `data/images/`，包含占位 SVG。没有本机占位标记时不会检查远端图片是否存在，直接返回库内合法路径；本次未联网验证图片可达性。

## 可选元数据入库与旧索引兼容

默认 `PRODUCT_SKUS_METADATA=false`，Milvus 仍只请求原有字段；旧集合无需变更，即可通过 manifest 和单品文件名关联。`PRODUCT_MANIFEST_PATHS` 默认值为：

```json
["data/docs_new", "data/docs_staging/manifest.csv", "data/docs/manifest.csv"]
```

可配置文件或目录的 JSON 数组，目录仅查找名为 `manifest.csv` 的文件。生产环境应指向**当前发布知识库对应的清单快照**，避免新稿与旧索引同名来源产生错误关联。默认值便于当前仓库使用；若部署不带 `docs_new`，应随已发布资料携带清单或启用元数据。清单只在首次需要回退时加载，进程内复用；更新后重启应用，不在请求中反复扫描磁盘。

原入库链路没有 `skus` 字段。本次提供显式选择的完整链路：

1. `load_document(..., metadata={"skus": [...]})` 支持可选 SKU；`Document.skus`、`Chunk.skus` 将关联携带到每个父子块，保持原有 `doc_id`、`parent_id`、`chunk_id` 的生成方式。
2. `ingest.content_merge --with-skus` 可将来源关联写到暂存目录的 `manifest.csv`，保留扁平复制后的 SKU 映射。该输出用于 SKU 关联，`facts` 留空；事实校验仍使用原始资料清单。未传参数时合并行为不变。
3. `ingest.run --with-skus` 从入库目录清单或单品文件名填入关联；无关联的文档写显式空数组。
4. `MilvusStore(skus_metadata=True)` 的新集合增加 `skus VARCHAR(4096)`，内容为 JSON 数组字符串，`null` 表示未提供。普通 Store 默认不加字段；如果已有集合缺少该字段，则拒绝直接写入并提示 staged 重建，不擅自修改在线集合。
5. 新发布清单的校验覆盖 SKU 字段，防止关联与构建输入不一致；默认不带元数据的旧行、旧发布清单指纹保持兼容。后续 `kb_switch` / verify 可按发布清单读取该字段，不要求另加开关。
6. 新版本发布后设置 `PRODUCT_SKUS_METADATA=true`，Retriever 才显式请求 `skus` 并携带到最终引用文档。启用前必须确认目标集合有该字段；切回旧集合时也应关闭此开关。

启用后的后续入库继续使用 `--with-skus`，保留关联；不要用不带此参数的旧脚本写入要求该字段的新集合。未启用这一选项的旧集合、旧脚本不受影响。

示例仅说明已有发布流程的新增参数，不表示本次执行过入库或切换：

```bash
cd backend
python -m ingest.content_merge --out data/docs_staging --faq-out data/faq_staging.csv --with-skus
python -m ingest.run --dir data/docs_staging --staged --with-skus --dry-run
# 后续按原发布流程构建、校验、切换；实际构建使用 --yes。
```

## Redis、一致性和性能

当前 `FaqCache` 只缓存 `FaqHit`，不是 RAG 回答缓存。`route="cache"` 是 FAQ 缓存命中，与 `route="faq"` 一样不带卡片，也不查询商品表；不会从 Redis 还原 `products`。本次不改缓存内容、键名、命名空间或 TTL。

RAG 每次确定最终引用后，最多做一次商品批量查询，避免每个来源一次查询；没有候选时完全不访问 MySQL。不缓存商品行、缺失结果或最终图片 URL，数据库更新和图片占位标记变化可在下一次请求反映。清单索引按进程缓存，配置和隐藏名单随应用生命周期生效。

查询在现有有界工作线程池运行，不阻塞事件循环、不复用跨线程 MySQL 连接；每次独立创建并关闭连接，连接/读写超时各 1 秒。`PRODUCT_CARDS_TIMEOUT_S` 默认 1 秒，覆盖卡片阶段的排队与读取，并给整请求保留约 50ms 收尾时间；预算不足则跳过卡片。已开始的同步线程超时后不能强制中断，但受线程池和驱动超时约束。

未来若新增 RAG 回答缓存，应缓存引用关联的 SKU / 来源及知识库版本，命中后仍按当前商品表、隐藏名单与图片配置重建卡片；不要持久化完整图片地址或永久复用卡片快照。该缓存当前不存在，因此未引入未使用的缓存协议。
