# 知识库扩容与回滚

本机制只管理知识集合，不修改 `data/docs`。现有在线 `Services → Retriever` 和入库 Store 的集合名均为 `kb_chunks`，没有集合名配置项，本次保持不变。发布后该名字作为 alias，实际集合使用 `kb_chunks_v<时间戳或序号>`。版本工具的 `--alias` 仅供独立集合使用；在线服务仍读 `kb_chunks`，不要以为此选项会改变在线配置。

## 安全默认值与运行条件

在 `backend/` 下执行以下命令，使用项目 Python 3.11 环境。CLI 用 `Settings(_env_file=None)`，只读取进程环境与默认值，不读取任何 `.env*`；实际运行时需要操作者预先设置 `MILVUS_URI`、本地模型路径、切块参数等进程环境。注意这与旧 CLI 自动读 dotenv 的行为不同。

`ingest.run` 默认完全离线 dry-run；所有写入、构建、迁移、切换、删除必须显式传 `--yes`。`--dry-run` 优先于 `--yes`。`kb_list` 只读 Milvus；`kb_switch --check` 显式运行本地编码和检索，未给 `--yes` 时仅检查，不改 alias。`--plan` 显式只读 Milvus 获取删除清单，不加载模型、不写集合。

真实入库沿用本地 BGE-M3、现有加载器和 splitter。模型必须已完整存在本地，编码器设置离线标志，不会自动下载。staging 完整构建需要额外存储；至少预留新旧两版及索引、加载内存。

## 推荐发布流程

1. 固定本次完整资料目录、模型及切块参数，先 dry-run，记录文档、父块、子块统计。
2. 构建独立 staging，检查输出版本名与统计。构建不会自动切换 alias。
3. 对该实体版本运行 `--check`，审阅样本命中和 Hit@5。
4. 带 `--check --yes` 发布；会再次校验、冒烟检查，通过后才切换。
5. 观察真实请求、引用来源、错误率和延迟，保留旧版作为回滚点。
6. 多次发布后，择期删除更老版本。当前版本及最近一次切换前的版本受保护。

```bash
cd backend
python -m ingest.run --dir data/docs --dry-run
python -m ingest.run --dir data/docs --staged                 # 仅离线预览
python -m ingest.run --dir data/docs --staged --version kb_chunks_v2026101901 --yes
python -m ingest.kb_list
python -m ingest.kb_switch --to kb_chunks_v2026101901 --check --eval-file data/eval_ragas_gold.jsonl --check-limit 20 --min-hit5 0.9
python -m ingest.kb_switch --to kb_chunks_v2026101901 --check --eval-file data/eval_ragas_gold.jsonl --check-limit 20 --min-hit5 0.9 --yes
python -m ingest.kb_drop --version kb_chunks_v2026101701       # 预览，仍执行保护检查
python -m ingest.kb_drop --version kb_chunks_v2026101701 --yes
```

首次全新部署可由 `kb_switch --yes` 创建 alias。若存在旧实体 `kb_chunks`，切换会拒绝，必须先迁移；普通就地入库和在线读取继续使用旧实体，不会自动迁移。

## 构建校验与重试

构建先将当前扫描结果的完整主键清单、文本/元数据 SHA-256 摘要、统计及创建时间写入发布状态文件，再建集合、逐批 upsert。每批写入检查向量数量、1024 维 dense、有限数值、稀疏权重和 UTF-8 字节上限。完成后 `flush → load → Strong query_iterator` 全量读取校验：必填字段非空、文本非空、dense 维度和有限数值、主键唯一，文档/父块/子块数量与本次离线切块快照完全一致，每行文本/元数据摘要一致。只有成功才标记 `ready`，切换前会重新执行此校验。

单独 dry-run 与实际构建之间若文件发生变化，两次统计自然可能不同；构建以当次加载到内存的快照为准，发布期间应固定资料。状态为 `building` 或校验失败的版本不能发布。`kb_list` 的实体数来自 Milvus stats 的 `row_count`，可能包含尚未压实的墓碑，不能据此断言实际有效行数“应为 79”，也不能用它判定旧块是否清理成功。发布校验使用 Strong iterator 读取的有效行、主键及内容摘要，与本次完整切块清单比对。

```bash
# 中断后使用相同输入、相同模型/切块参数与版本名重跑；稳定主键使批次覆盖幂等。
python -m ingest.run --dir data/docs --staged --version kb_chunks_v2026101901 --yes
# 输入发生变化，或希望丢弃部分构建：明确重建同一未发布 staging。
python -m ingest.run --dir data/docs --staged --version kb_chunks_v2026101901 --rebuild --yes
```

重试会重新编码并 upsert 全量块，不会从批次游标续传。输入摘要不同会拒绝普通重试，需要新版本或 `--rebuild`。模型权重身份不在摘要中，操作者必须固定模型；不能在重试中换模型。当前或任何曾发布版本都不能被 staged 重写，包括回滚点。也可用受保护的 `kb_drop` 删除未发布 staging，再重新构建。

## 检索冒烟

默认读取 `data/eval_ragas_gold.jsonl`，只选 `answerable=true` 且有 `expected_doc` 的行，按文件顺序等间距取至多 20 条固定查询（可用 `--check-limit` 调整，`--eval-file` 指定文件）。使用现有 Retriever 的 dense+sparse 混合检索和父块去重，关闭重排，只在前 5 个结果中按 `source` 或 `doc_id` 精确匹配任一可接受文档统计 Hit@5。输出每题原始标注、结果及总分；无有效题、非法标注或阈值、校验失败、编码/检索错误、低于阈值均拒绝切换。

`expected_doc` 向后兼容单个字符串，也支持非空字符串列表，例如 `"payment_invoices.md"` 或 `["payment_invoices.md", "payment_invoice_correction_case.md"]`。只加入经阅读确认包含本题事实答案的文档，保留原规则文档；同主题、标题相似或回答看似正确都不是自动放行依据。空列表、空白字符串、非字符串成员及其他类型均报错，即使该行不会被抽样；缺省或 `null` 继续表示没有来源参考，不参与来源统计。

`eval.run_eval` 的 `source_hit` 与 `eval.check_retrieval` 同样支持任一来源命中，各自保持原有匹配方式：冒烟精确比较 source/doc_id；检索评测比较 source 的文件名并报告最先命中的排名；端到端评测比较在线返回的已引用来源 doc_id（兼容文件名、路径文件名和入库稳定摘要）。未引用候选不计为端到端命中，带参考的失败或拒答仍计入分母。`ragas_eval collect` 提前校验并原样保留字符串或列表，不用来源列表代替回答质量指标。

本次逐题补充标准集 4 题、多轮集 5 题、金标集 25 题的可接受案例来源，未修改原问题、参考答案或路由。口语集有 8 题原为 `null`，现新增原规则文档及案例参考，带参考的题数从 8 增到 16；其余 `null` 和商品总览题保持原标注。因此新旧口语来源命中率分母不同，不能直接比较；其他集合虽题数不变，可接受来源集合及文件指纹也已变化。报告比较应固定评测文件版本及指纹。

`--check --yes` 在全量校验和检查通过后继续读取当前 alias，再执行绑定。检查现在直接借用 manager 的 Store 客户端，对指定实体版本检索，不改变 Store 集合名，也不在成功或异常路径中关闭连接。依据线上 pymilvus 2.5.18 的已确认实测，相同 URI 等参数创建的客户端可能共用连接别名；关闭检查客户端会连带使 manager 后续调用抛 `ConnectionNotExistException: should create connection first`。借用客户端避免建立第二个连接对象，也不需要在检查后重连或重试写操作；单独调用 `smoke_check` 时同样不关闭可能共享的连接，由进程结束回收。旧故障发生在 alias 写入前，检查通过日志不代表已发布，应以命令退出状态、最终输出和 `kb_list` 为准。

这是独立的最小检索检查，不代表在线重写、多轮对话、重排或回答质量评测；默认 0.9 也不是已证明适合当前语料的阈值。总控需要用真实本地模型/Milvus 实测后确认阈值，不能为了发布而无审查降低阈值。

## 回滚与删除保护

```bash
python -m ingest.kb_list
python -m ingest.kb_switch --to kb_chunks_v2026101801          # 预览
python -m ingest.kb_switch --to kb_chunks_v2026101801 --check --min-hit5 0.9 --yes  # 检查通过后回滚
```

切换通过一次 `alter_alias` 完成，旧集合保留，不使用 drop/create alias。回滚使用同一命令，仍要求目标清单为 ready、全量校验通过。删除保护按实际切换历史计算，**不是按版本名/创建时间排序**：例如 v1→v3→v2，保护 v2 和 v3。回滚后原来的新版变成最近旧版，依然受保护。未登记集合一律拒删；alias 与记录历史不一致时拒删，避免外部手工切换或状态丢失导致误删。

## 旧部署一次性迁移

旧实体 `kb_chunks` 与同名 alias 不能共存，因此需要维护窗口：暂停入口流量和所有入库任务，备份 Milvus 与发布状态，再执行：

```bash
python -m ingest.kb_migrate                                  # 仅打印计划
python -m ingest.kb_migrate --yes
python -m ingest.kb_list
```

迁移先读取旧行、登记并校验清单，将旧实体 rename 为 `kb_chunks_v0`，加载校验后创建 `kb_chunks` alias 指向 v0。旧实体缺少必填字段、空文本或非法向量会拒绝迁移，需要操作者处理；原有旧块会原样登记，不会在迁移中自动清理。rename 与 create_alias **不构成跨操作原子事务**，中间 `kb_chunks` 会短暂不可用，因此不能宣称无停机迁移。v0 已存在且旧实体仍存在会拒绝覆盖。进程在 rename 后中断，可用同一个状态目录重跑迁移恢复；已有 alias 时不会重复重命名。

`kb_migrate` 只改集合名和 alias，**不会清理脏数据或将 161 个旧块变成 79 个当前块**。需要 161→79 时，应先在维护窗口单独运行 `ingest.run --dir data/docs --sync-delete --plan`，审阅旧块主键后再用相同目录和切块参数执行 `--sync-delete --yes`；核对有效行及内容后再迁移。`--sync-delete` 默认保留其他文档，若差异来自未扫描文档，需先核对资料根目录，按下节的高风险流程单独处理。

迁移在 rename 前持久化 `rename_pending`，rename 后持久化 `renamed_pending_alias`。创建 alias 失败时保留 pending；保持入口和入库暂停，使用同一个 `--state-dir` 重跑 `kb_migrate --yes`。恢复会识别 rename 已完成的实体，重新加载并校验清单，然后补建 alias；若 alias RPC 已成功则补记历史。网络/权限错误继续报错，集合冲突或内容校验失败须先人工核对，不能通过清空 pending 或换状态目录绕过。

迁移之后启动/恢复服务，确认真实检索命中。一旦发布其他版本，v0 即可作为回滚目标；仍受最近旧版保护。

## 就地更新与旧块清理

```bash
python -m ingest.run --dir data/docs --yes                   # 显式就地 upsert，不清理
python -m ingest.run --dir data/docs --sync-delete --plan    # 只读扫描并输出过期主键
python -m ingest.run --dir data/docs --sync-delete --yes
# 仅当 data/docs 是这个集合的完整资料根目录时，才使用 prune-missing：
python -m ingest.run --dir data/docs --sync-delete --prune-missing --plan
python -m ingest.run --dir data/docs --sync-delete --prune-missing --yes
```

`--sync-delete` 默认关闭，需 `--yes` 才删除。扫描 Store 中的精确 `(doc_id, source)`，只选本次扫描文档中已经不再生成的 chunk_id；其他文档默认保留。额外给 `--prune-missing` 才选出本次未扫描到的文档。删除清单在写入前完整打印并 flush stdout；全部 upsert 成功后才按明确主键分批 delete，再 flush/load。删除失败可重跑。没有模糊匹配，不执行 `source like ...`。空目录拒绝执行，不提供清空全集的捷径。

**`--prune-missing` 是高风险操作，必须先单独运行 `--sync-delete --prune-missing --plan` 并逐项审阅。** 它会把本次目录未扫描到的其他资料也列为删除对象；只有确认目录是集合的完整资料根目录、删除范围正确后，才执行对应的 `--yes`。这是运维前置要求，CLI 不会持久化或强制检查是否已经执行过 `--plan`。

完全离线的 `--dry-run` 不连接 Milvus，无法计算旧块清单；使用 `--plan` 做只读对比。`--plan` 和 `--dry-run` 不能同用。分批就地更新/删除不是事务，失败可能出现部分更新，且已删除数据无法靠 alias 回滚到修改前；推荐版本发布。资料子目录的 source 相对路径可能变化，`--prune-missing` 用错根目录会删除其他资料，必须先审阅计划。

就地命令在发布锁内解析 alias 并固定为实体名，批次不会因本工具的切换而写到不同集合。对已登记的当前版本进行就地更新，会先将清单状态标记 `modified-in-place`，防止后续用旧清单误发布；它继续服务，但不能再作为 ready 目标发布。需要重获可回滚快照时应完整构建新版本。

## 在线感知、加载与状态保管

Retriever 每次检索都传 `collection_name="kb_chunks"`，不把 alias 解析结果缓存成实体名；服务代码和配置无需为版本发布改名，也未引入后台线程。正常 alias 切换设计上不需要重启在线进程，后续请求由服务端解析到新集合；需在真实 SDK/服务端上验证长连接客户端的 alias 缓存行为。一个请求包含多次 hybrid_search 时，切换恰好发生在两次 RPC 之间可能读到两版，这里不提供请求级快照。

Store 在构建、切换/回滚校验时对目标实体执行 flush/load；load 早于 alias RPC，因此不需要在在线进程对 alias 再 load 一次。旧集合保持加载，避免在途请求失败并加快回滚，代价是内存。确认流量排空后可由运维显式调用 Store.release(旧实体名)，不得释放当前目标；本工具不会在切换后立即 release。择期 drop 会移除实体资源，回滚目标会重新 load。

默认状态目录在仓库根 `.kb-state/`，按 URI+alias 哈希隔离；所有发布命令也可统一传 `--state-dir /持久卷/kb-state`。必须备份且共享同一目录，**不能每次换目录、换 URI 写法或在不同发布机器各存一份**。状态保存创建时间、逐行摘要、构建状态和切换历史；迁移 v0 的创建时间是登记时间，非旧集合真实创建时间，未登记集合时间显示 null。保存使用同目录临时文件原子 replace；切换有写前日志，处理 alias RPC 成功但保存历史前退出的情形。下次显式写操作会核对 pending；`kb_list` 会显示 pending 供检查。

Unix `fcntl` 锁只协调共享目录内的本工具发布者；不提供跨主机分布式锁、磁盘断电事务或外部管理员并发操作保护。只允许一个发布控制面。目录损坏/丢失、外部改 alias、跨 URI/跨库操作时需先人工核对和恢复记录，不要通过新建空状态目录绕过保护。staging 全量文本与 dense 校验是 O(块数)，清单也占 O(块数) 本地空间，超大库需另做可扩展元数据存储。本次不更改 FAQ 或 pipeline。

## 验证范围与总控实测项

依赖基线是 `backend/uv.lock` 的 `pymilvus==2.5.18`。SDK 操作集中在 `app/retrieval/store.py`，使用 MilvusClient 的 list_collections/list_aliases、create/alter_alias、rename_collection、query_iterator、delete(ids)、flush/load、stats、drop/release。alias 查询兼容 `list_aliases` 实际返回的 `{"aliases": [...], "collection_name": ..., "db_name": ...}` 和旧 list 形态，仅在成功枚举后认定不存在；RPC 异常原样传播。该路径不依赖 `describe_alias` 的异常码。假客户端测试不证明真实服务端兼容性，测试过程不得连接真实 Milvus。

总控须在隔离测试集合核对：2.5.18 的实际签名/返回格式、服务端与客户端版本兼容、alias/实体 has_collection 语义、rename 的索引/加载状态、单次 alter_alias 原子性、长驻在线客户端切换感知、Strong iterator 的全量性与向量返回格式、flush/load 完成语义、delete 的墓碑可见性与 stats 延迟、旧版 release 后回滚 reload、RPC 超时后的 pending 恢复，再使用真实查询实测 Hit@5。首次迁移必须先在副本验证。

`test_ingest_versioning.py` 使用内存假客户端覆盖构建不切换、字段/维度/统计/摘要失败、原子切换与回滚、删除保护、旧部署、迁移、alias 写入、重试/重建、切换中断恢复、sync-delete 隔离、CLI 安全默认值和冒烟阈值拒绝。alias 测试同时覆盖 SDK dict/旧 list、缺失别名、无效返回形态、网络/权限异常及 create/alter 分支；迁移测试覆盖 rename 后 alias 创建失败、进程在阶段保存前退出、alias 成功但历史未保存、旧 pending 格式、内容校验失败及集合冲突。在线检索测试补充同一个 Retriever 两次请求使用 alias 的契约。已有 CLI 测试更新为显式 `--yes` 并替换禁 dotenv 的配置入口。完整 pytest 仍需项目 Python 3.11 和依赖。
