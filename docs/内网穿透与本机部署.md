# 内网穿透与本机演示部署

访问链路：`rag.ailingma.com` → 穿透服务的 HTTP/HTTPS 隧道 → 本机 Caddy → 前端构建文件或 `127.0.0.1:8010`（FastAPI）。HTTP 使用本机 `8080`，HTTPS 使用本机 `8443`。

## 隧道要求

按下面的本地地址准备两条隧道，或使用等效的反向代理转发。不要把穿透客户端的连接端口写入 DNS，也不要把它附加到网站访问地址。

| 用途 | 本地 IP | 本地端口 | 绑定域名 |
| --- | --- | --- | --- |
| HTTP | `127.0.0.1` | `8080` | `rag.ailingma.com` |
| HTTPS | `127.0.0.1` | `8443` | `rag.ailingma.com` |

穿透节点的对外域名由 DNS 的 CNAME 指向。访问密钥只在穿透客户端本地填写，不放入本仓库、截图或聊天。

## 本机准备

以下命令均从仓库根目录执行；需要已安装依赖、准备好根目录 `.env`、本地模型，并完成文档及 FAQ 入库。Caddy 使用本机已经安装的程序。

1. 检查依赖服务：

   ```bash
   docker compose ps
   ```

2. 构建前端：

   ```bash
   cd frontend
   npm run build
   cd ..
   ```

   构建应使用真实服务模式，API 基址为空以走同源入口；不要配置指向访客自身电脑的 localhost API 地址。

3. 在一个终端运行后端：

   ```bash
   sh deploy/start-local.sh
   ```

4. 在另一个终端从仓库根目录运行网站入口：

   ```bash
   ECOMRAG_FRONTEND_DIR="$PWD/frontend/dist" caddy validate --config deploy/Caddyfile --adapter caddyfile
   ECOMRAG_FRONTEND_DIR="$PWD/frontend/dist" caddy run --config deploy/Caddyfile --adapter caddyfile
   ```

5. 打开 `http://127.0.0.1:8080`，确认页面及聊天可用。后端状态可在本机通过 `http://127.0.0.1:8010/health` 检查。

后端与 Caddy 均以前台命令运行，关闭对应终端或按 Ctrl+C 将停止对应服务。没有配置开机自启。

## DNS 与穿透客户端

在 `ailingma.com` 的 DNS 服务商解析设置中添加：

| 字段 | 内容 |
| --- | --- |
| 记录类型 | CNAME |
| 主机记录 | rag |
| 解析线路 | 默认 |
| 记录值 | 穿透服务提供的节点域名 |
| TTL | 默认 |

若已有 `rag` 同名记录，先核对冲突，不要直接覆盖其他用途的记录。无需 DNS 服务商的 API 密钥。

隧道变为在线且 DNS 生效后，通过 `http://rag.ailingma.com` 测试。在部署机器上打开成功，不能代表外部网络也可访问；应另外用外部网络或手机网络验证页面能打开、聊天可完成，以及 SSE 事件逐步到达。

## HTTPS 配置

`deploy/Caddyfile` 已配置 `rag.ailingma.com` 的自动证书管理。Caddy 通过现有 HTTP 隧道的公网 80 端口完成 HTTP-01 域名验证，并在 `127.0.0.1:8443` 提供 TLS。

在穿透服务中另建 HTTPS 隧道：

| 字段 | 内容 |
| --- | --- |
| 类型 | HTTPS |
| 本地 IP | 127.0.0.1 |
| 本地端口 | 8443 |
| 绑定域名 | rag.ailingma.com |
| 自动 HTTPS | 关闭，本机 Caddy 已处理 TLS |
| 创建 HTTP 重定向 | 关闭，保留现有 HTTP 隧道 |

CNAME 保持 `rag` 指向穿透节点域名。创建后在穿透客户端中启用新增隧道，再访问 `https://rag.ailingma.com`，公网网址不附加 `8443`。

保留 HTTP 隧道，供当前 HTTP 访问及自动证书续期使用；外部 HTTPS 验收完成前不强制将 HTTP 重定向。证书与私钥存放在 Git 忽略的 `logs/caddy-data/`，不要提交、分享或在正常维护时删除该目录。

上线检查应使用系统证书信任验证 HTTPS，不能通过忽略证书错误来判定配置成功。

## 当前限制

- 演示机、Docker、后端、Caddy 和穿透客户端需要持续运行。
- Caddy 已配置 HTTPS，外网 HTTPS 是否可用仍取决于证书签发和 HTTPS 隧道的在线状态；HTTP 入口仅用于公开样例测试与域名验证。
- 不信任未经核实的转发 IP 头。`deploy/start-local.sh` 设 `RATE_LIMIT_IP_ENABLED=false`，暂时只使用每会话 50 次/分钟的额度，不再让所有访客共用回环 IP 桶；代码默认仍启用 IP 限流。每会话日额度默认 200，不因并发调到 50 而降低。session 可以更换，这只是避免误伤的临时措施。
- 若 HTTP 隧道把真实 IP 追加到 `X-Forwarded-For` 最右侧，前面的值可被访客伪造；部分 HTTPS 隧道需两端配合 Proxy Protocol。当前 Caddy 与隧道未完成该对接，不能直接开启对原始 XFF 的信任。完成透传验证后，应恢复 IP 与会话双重限流。
- `admin off` 禁用 Caddy 管理接口；Caddy 与后端只监听回环地址。
- 不映射 MySQL、Redis、Milvus 或 Vite 开发服务器。

参考：[Caddy 自动 HTTPS](https://caddyserver.com/docs/automatic-https)、[Caddy 反向代理说明](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)。
