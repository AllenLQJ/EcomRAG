# 内容集成与一致性检查

## 使用方式

在仓库根目录运行（也可在 backend 下省略 `PYTHONPATH=backend`）。两个内容工具只读取本地 CSV/Markdown，不加载应用配置、不访问 `.env*`、不联网、不启动模型或真实服务。

```bash
PYTHONPATH=backend python -m ingest.content_check
PYTHONPATH=backend python -m ingest.content_check --root data/docs_new --facts data/policy/policy_facts.csv --json content-report.json
PYTHONPATH=backend python -m ingest.content_check --root data/docs_generated --json product-report.json
PYTHONPATH=backend python -m ingest.content_merge --out data/docs_staging --faq-out data/faq_staging.csv --dry-run
PYTHONPATH=backend python -m ingest.content_merge --out data/docs_staging --faq-out data/faq_staging.csv
```

检查器有错误或警告均返回 1；只有成功和跳过提示时返回 0。合并器校验或写入失败返回 1。`--json` 保存与标准输出相同的完整 JSON，目标父目录需事先存在。相似度阈值可通过 `--similarity-threshold 0.6` 调整，范围为 0–1，严格大于阈值才报告。

默认扫描 guides、service、order_promo、account_store 四组，也扫描新增的其他子组。不存在的组提示并跳过；已存在的组必须提供三个清单。可单独指定一个组。对没有 manifest 的独立平铺文档目录（如 docs_generated），只检查结构、数字、禁用内容、商品参数和文档相似度，不要求补 manifest/FAQ，也不检查现有 FAQ。缺少可选比对目录、商品表时提示跳过相应部分；缺失事实表时数字仍核对可用商品规格，已经声明但无法核实的规则编号仍报告错误。跳过提示不代表该部分已验收。

## 类别与数据库兼容

合法类别统一为 `after_sales`、`logistics`、`payment`、`product`、`promotion`、`account`、`store`。FAQ 导入与审计共享同一类别集合及单行校验。文档按文件名的 `<category>_` 或 `<category>-` 前缀分类；`account_security_` 归 account，store_ 归 store。未知前缀维持原加载器默认 product 的行为，manifest 必须与该结果一致。旧五类别映射及无前缀默认值保持兼容。

仓库 `backend/sql/init.sql` 中 faq_pairs.category 已是 VARCHAR(100)，新增类别不需要改表。旧部署若为 ENUM，可在有数据库维护授权时运行：

```bash
PYTHONPATH=backend python -m ingest.migrate_faq_categories
```

迁移先 SHOW COLUMNS，只对 ENUM 执行 `ALTER TABLE faq_pairs MODIFY COLUMN category VARCHAR(100) NOT NULL DEFAULT ''`，保留已有类别值；再执行时不发 ALTER。合法值由共享的 Python 校验限制。迁移命令只读进程环境配置，禁用 dotenv；它会连接 MySQL，有 DDL 隐式提交和可能锁表的影响。本任务只用假连接验证迁移，未执行真实数据库迁移。

## 检查与分级

| 检查 | 判定和修复方式 |
| --- | --- |
| manifest | 表头和顺序严格为 file,title,category,facts,skus；每篇 md 恰好一条记录，不得缺文件、多记录或多文件；标题与一级标题相同，类别与前缀一致。按报告校对文件名、清单和标题。 |
| 结构 | 有一级标题，至少三个 `##` 二级小节。整篇 900–1500 字，每节 120–400 字；三级标题及内容计入其二级小节。字符计数不含空白和 Markdown 的 #、*、反引号、竖线，其余标题、正文、数字和标点均计数。 |
| 长度分级 | 超出目标区间但仍在下限的 80% 至上限的 120% 范围内为 warning；超出这层缓冲为 error。小节不足或缺标题始终为 error。DOC_MIN/MAX_CHARS、SECTION_MIN/MAX_CHARS、LENGTH_ERROR_MARGIN 常量可统一调整。 |
| 数字出处 | 阿拉伯数字加单位（包括计数单位）仍须有出处；中文数字仅提取明确的时间、金额、百分比及物理单位，忽略“两款、一款、一个、两个、一条、一次、一时、一点、三款、一定”等计数/指代短语。三个工作日、十二个月、七天仍需来源；常用中文整数统一到阿拉伯数字，百分之十五统一为 15%，¥99 统一为 99元。一般数值允许来自事实表 value 或商品 specs，非商品内容的金额只允许来自事实表 value。忽略空白、统一部分范围连接符和全半角，不做单位换算或推算。未知数字输出文件、数字、上下文。 |
| 规则追溯 | manifest.facts 和 faq_manifest.facts 均需存在于事实表；支持分号、逗号、竖线或空白分隔。编号重复或为空的事实表记录也报错。rule_references 含所有事实编号及引用文档，包括零引用编号。 |
| 文档相似度 | 复用 products.text_ngrams 的小写、去标点和下划线规范化及字符 3-gram 集合；Jaccard 为交集/并集。所有新文档两两比较，不限制类别；另与 docs、docs_generated 的同类文档比较，跳过同一路径自身。默认严格大于 0.6 报 error，输出另一文件和分数。 |
| 禁用内容 | 商品组 guides、docs_generated 保留 products.FORBIDDEN 的价格、售价、金额、币符号、库存、现货约束；普通独立目录中的 product 类别同样适用。service、order_promo、account_store 以及非商品类别的独立文档/FAQ 允许讨论价格保护、运费门槛、库存等主题，但金额必须在事实表 value 中存在，不能只借用商品 specs。商品限制按组判定，不因 FAQ 自填类别变化而绕过。各组仍检查真实品牌、医疗及不具备功能的肯定表述。明确否定、否定谓语下的并列项、“不构成”“没有相关说明”和受限的后置否定放行；逗号、换行、转折和新肯定谓语终止豁免，双重否定不能据此放行。 |
| FAQ | FAQ CSV 表头严格为 question,answer,category；字段非空，问题最多 500 字、答案最多 10000 字，类别合法。含现有 FAQ 和各组 FAQ 的所有问题，两两检查缓存 normalize 后相同或字符 3-gram Jaccard 严格大于 0.8，均报 error，不静默覆盖重复问题。 |
| FAQ 来源 | faq_manifest 表头严格为 question,source_file,facts；每个问题恰好一个映射，不能有多余问题；source_file 必须是本组实际加载的相对文件名，facts 合法。答案每个数字单位必须出现在对应文档中，即使存在于事实表也不能替代来源文档。 |
| 商品一致性 | products.read_products 先执行已有的商品表 validate、能力、禁用词、规格与相似度校验。manifest SKU 必须存在；商品文件名对应的标题名称须与表一致，系列型号及显式 SKU 不能杜撰。正文按名称/SKU/无歧义型号绑定局部数值，参数表按当前标题下的 SKU 比较规格键和值；明确参数键另外核对该键的数字。 |

除长度的缓冲区及下述案例时间位置外，校验失败均为 error；不存在目录等为 info。报告含 summary、groups、documents、issues、rule_references、affected_documents；逐文档成功项也列出文件和类别。修复时先处理 csv、manifest、未知规则/SKU 等基础问题，再检查数字、参数、FAQ 来源，最后评估长度和相似度。按 `code` 过滤 issues，每次修复后重新运行。错误条数是出现次数，不等于问题文件数。

显式“例如/比如/案例/假设”等上下文里的时间位置（如“例如，顾客在签收第10天联系客服”）若没有来源，保留 unsourced_number，但降为 warning，并附 reason 提醒人工复核。案例可以构造时间位置，不一定是在新增退货期限；因此不直接认定规则错误，也不静默放行。没有举例标记的“签收第10天”、带规则/必须/要求等约束措辞的数字、举例中的金额仍为 error。FAQ 答案缺少对应文档出处的 faq_number 也始终为 error。原有标题一致性、900–1500/120–400 字区间及其分级、重复/相似度阈值均未调整。

## 规则变更后重审

规则维护者修改事实表后，将需要重审的规则 status 标为 new，再运行检查。`affected_documents` 按规则编号输出受影响文档，包括 FAQ 来源映射带来的引用；相同文档去重。`rule_references` 可查询任意规则（不限 status）。例如：

```bash
python -c 'import json; r=json.load(open("content-report.json")); print(r["affected_documents"]); print(r["rule_references"].get("DEL-02", []))'
```

据清单复核正文、FAQ 答案及数字出处；审核后再由规则维护者调整状态。引用未写入 manifest/facts 的隐式依赖无法自动追溯，必须同步补齐元数据。

## 合并规则与保护

按文件名构建完整发布候选集：先保留 docs 全部文档，再用 docs_generated 覆盖 docs 的同名文件（含 product_catalog.md 和 after_sales_warranty.md），最后并入 docs_new 各组文档。仅这一步 generated 对原 docs 的同名替换享有覆盖权限；其他同名不同字节内容一律报错，同名相同字节去重。文件输出为平铺目录。旧商品文件的下划线名与新文件的连字符名是不同文件，会同时保留。

FAQ 依次追加 data/faq.csv 和 docs_new 各组 faq.csv，严格保持 question,answer,category 表头，不自动去重；先运行检查器处理重复问题。合并前验证文档可加载、FAQ 合法并完成切块统计。统计复用 ingest.run.analyze_documents，使用默认父块 1200、子块 300、重叠 50，不加载配置或写数据库；类别数量按最终保留文档计算。

`--dry-run` 全程不产生输出目录和 FAQ 文件。实际写入只允许 data/docs_staging 和 data/faq_staging.csv；两个目标中任一已存在，都必须加 `--force`，预览也适用。`--force` 会清空旧文档输出再写完整候选集，并覆盖 FAQ；不能写到其他目录、原始 FAQ 或经符号链接指向的目标，不能触碰输出目录中的 `.env*`。源目录永不修改。先解决所有输入错误和冲突再写；磁盘写入阶段遇到 I/O 故障仍可能留下部分输出，应修复后以 --force 重建，工具不负责原子发布。

## 已知局限

数字检查判断出处，不判断该规则是否适用于当前语境；不能从“已找到相同数字”推断事实正确。常用中文整数会规范化，中文泛指计数短语不检查；单位别称、不同小数写法不互换，支持单位列表 UNITS/CHINESE_UNITS 可扩展。没有单位的裸数字、复杂中文小数、复杂公式、表格省略单位和时钟形式无法完整检查。案例识别采用有限文字模式，warning 仍需人工核对，不能视为审核通过。

相似度是字面重合度，无法识别所有近义改写；模板、参数表与总览复述会提高分数，报告需人工裁定。短于 3 字的问题可能产生空 n-gram 集合，属于保守提示。真实品牌和医疗词表有限，隐晦功能承诺、复杂否定、引用及多层语义不能完全识别。

SKU 正文绑定只覆盖名称/SKU 后的局部子句和带主体的参数表；跨段代词、省略、多个型号同句的复杂比较需人工核对；物理数值集合匹配不能完整证明模式、组件、测量条件一致。结构检查按 Markdown 标题的文字形式识别，不是完整 Markdown AST，代码围栏中的示例标题也可能计入。

本轮仅修改 content_check.py、相关三个测试文件和本文档，没有提交，也没有改动数据。误报根因与修复如下：
